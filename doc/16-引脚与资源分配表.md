# 引脚与外设资源分配表（补充资料）

> 本文把项目实际占用的**引脚、DMA 通道、中断向量、定时器和时钟**集中成表，
> 便于核对硬件、排查"某个功能没反应"以及改板时评估影响。
> 采样通道的电气换算见[采样与板级](03-采样与板级.md)，参数的默认值见[参数与调参速查](10-参数与调参速查.md)。
> 引脚与通道号的权威来源是 `Core/Src/*.c` 的 CubeMX 注释与 `Observer.ioc`；**改动后本文可能陈旧，以源码为准。**

---

## 1. 时钟树

| 节点 | 配置 | 结果 |
|---|---|---|
| HSE | `BOARD_HSE_HZ` = 16 MHz（24 MHz 为跨板验证分支） | 16 MHz |
| PLL | M=4（16 MHz 分支），目标 170 MHz | **SYSCLK = 170 MHz** |
| AHB | 不分频 | HCLK = 170 MHz |
| APB1 | `RCC_HCLK_DIV1` | PCLK1 = 170 MHz |
| APB2 | `RCC_HCLK_DIV1` | PCLK2 = 170 MHz |
| TIM1 计数时钟 | `Prescaler = 0` | 170 MHz |
| TIM6 计数时钟 | `Prescaler = 169`，`Period = 999` | 1 kHz 更新 → **1 ms** |
| FDCAN1 内核时钟 | `RCC_FDCANCLKSOURCE_PCLK1` | 170 MHz |
| ADC12 外设时钟源 | `RCC_ADC12CLKSOURCE_SYSCLK`，`ClockPrescaler = ADC_CLOCK_SYNC_PCLK_DIV4` | 同步模式，按 HCLK/4 计 |

> 选错 HSE（16 vs 24 MHz）会同时打乱**系统主频、串口波特率和 CAN 位定时**，
> 症状通常是串口乱码或完全无输出。判定方法见[故障排查手册 §2.1](11-故障排查手册.md#21-串口完全没有输出)。

## 2. 定时器与硬件加速器

| 外设 | 角色 | 关键配置 |
|---|---|---|
| **TIM1** | 三相 PWM + ADC 注入触发 | 中心对齐 1，`Prescaler=0`，`Period=3399` → `(3399+1)×2/170 MHz = 40 µs`（**25 kHz**）；CH1~CH3 PWM1 互补；CH4 `Pulse=3398`；`MasterOutputTrigger = TIM_TRGO_OC4REF`；`RepetitionCounter=0`；死区 `DeadTime=90`（约 529 ns），`OSSR/OSSI` 使能 |
| **TIM6** | CAN 调度节拍 | 向上计数，1 ms 更新；中断里进 `MotorProtocol_TimerTick()` |
| **SysTick** | HAL 毫秒时基 | 由 HAL 初始化，`HAL_GetTick()` |
| **CORDIC** | 硬件三角函数 | 正余弦与 atan2；中断优先级 0 |
| **DWT** | 周期计时 | `bsp_dwt.c`，用于 `status` 的 `TIMING` 行与微秒延时 |

关于 TIM1 的两点值得记住：

1. **CH4 没有引脚。** CubeMX 没有为 CH4 配置任何 GPIO，它只作为内部触发源
   （`TIM_TRGO_OC4REF` → ADC 注入组）。所以 `FOC_PWM_Start()` 里对 `TIM_CHANNEL_4`
   调用 `HAL_TIM_PWM_Start()` 不需要引脚也能工作。
2. **Pulse=3398 紧贴 ARR=3399**，把注入采样点推到载波末端附近（中心对齐的波谷/波峰区），
   目的是避开上下管切换瞬间的振铃。改这个值等于移动采样时刻。

## 3. 引脚分配

由各外设的 `HAL_xxx_MspInit()` 配置（`gpio.c` 的 `MX_GPIO_Init()` **只开时钟、不配引脚**）。

### 3.1 功率级与 PWM

| 引脚 | 功能 | 复用 | 说明 |
|---|---|---|---|
| PA8 | TIM1_CH1 | AF6 | U 相上管 |
| PA9 | TIM1_CH2 | AF6 | V 相上管 |
| PA10 | TIM1_CH3 | AF6 | W 相上管 |
| PB13 | TIM1_CH1N | AF6 | U 相下管（互补） |
| PB14 | TIM1_CH2N | AF6 | V 相下管（互补） |
| PB15 | TIM1_CH3N | AF4 | W 相下管（互补） |

> 这六个引脚在 `main()` 最开始、任何 HAL 初始化之前，由
> `MotorApp_ForcePowerStageSafe()` 先设为**推挽输出低电平**，之后才由 `tim.c` 切成复用功能。
> 这个先后顺序是上电安全的前提，**不要改**。

### 3.2 模拟输入

| 引脚 | 功能 | 进入 | 说明 |
|---|---|---|---|
| PA0 | ADC1_IN1 | 规则组 R1 | 母线电压（100k/5.1k 分压） |
| PA1 | OPAMP1_VINP | — | U 相电流运放同相输入 |
| PA3 | OPAMP1_VINM | — | U 相电流运放反相输入 |
| **PA2** | OPAMP1_VOUT / ADC1_IN3 | 注入 R1 | Ia |
| PA7 | OPAMP2_VINP | — | V 相电流运放同相输入 |
| PA5 | OPAMP2_VINM | — | V 相电流运放反相输入 |
| **PA6** | OPAMP2_VOUT / ADC2_IN3 | 注入 R1（ADC2） | Ib |
| PB0 | OPAMP3_VINP | — | W 相电流运放同相输入 |
| PB2 | OPAMP3_VINM | — | W 相电流运放反相输入 |
| **PB1** | OPAMP3_VOUT / ADC1_IN12 | 注入 R2 | Ic |
| PB12 | ADC1_IN11 | 注入 R3 | U 相端电压 |
| PB11 | ADC1_IN14 | 注入 R4 | W 相端电压 |
| PA4 | ADC2_IN17 | 注入 R2（ADC2） | V 相端电压 |

`SharedAnalog_PA2 / PA6 / PB1` 是 CubeMX 对"同一引脚既是运放输出又是 ADC 输入"的命名。

> **代码里 OPAMP 为 standalone 模式、`InternalOutput = DISABLE`**，
> ×24 增益与 1.65 V 偏置都由**外部电阻网络**决定。换板或改电阻后必须同步
> `Core/Src/foc_math.c` 的 `foc.current.gain_a/b/c`。

### 3.3 通信

| 引脚 | 功能 | 复用 | 说明 |
|---|---|---|---|
| PB6 | USART1_TX | AF7 | 串口控制台发送 |
| PB7 | USART1_RX | AF7 | 串口控制台接收 |
| PA11 | FDCAN1_RX | AF9 | CAN 接收 |
| PA12 | FDCAN1_TX | AF9 | CAN 发送 |

USART1：**2,000,000 baud**，8 位、1 停止位、无校验、无流控，16 倍过采样，FIFO 模式**关闭**。

FDCAN1：`FrameFormat = FDCAN_FRAME_FD_NO_BRS`（BRS 关闭），
Nominal/Data 各 `Prescaler=5`、`TimeSeg1=28`、`TimeSeg2=5`、`SyncJumpWidth=1`，
即 `34 TQ`，`170 MHz / 5 / 34 = 1 Mbit/s`（采样点约 85.3%）。
`AutoRetransmission = DISABLE`、`TxFifoQueueMode = FDCAN_TX_FIFO_OPERATION`、`StdFiltersNbr = 2`。

| 引脚 | 功能 |
|---|---|
| PA13 | SWDIO |
| PA14 | SWCLK |

## 4. DMA 通道

四个通道全部来自 **DMA1**，模式都是 `DMA_NORMAL`（不是循环模式），优先级都是 `LOW`。

| 通道 | 请求 | 方向 | 数据宽度 | 用途 |
|---|---|---|---|---|
| DMA1_Channel1 | `DMA_REQUEST_USART1_RX` | 外设→内存 | 字节 | 串口接收；到事件中断后由软件重启 |
| DMA1_Channel2 | `DMA_REQUEST_USART1_TX` | 内存→外设 | 字节 | 串口发送（文本与波形共用） |
| DMA1_Channel3 | `DMA_REQUEST_ADC1` | 外设→内存 | 半字 | ADC1 规则组 DMA 读取 |
| DMA1_Channel4 | `DMA_REQUEST_ADC2` | 外设→内存 | 半字 | ADC2 规则组 DMA 读取 |

> **注入组不走 DMA**：注入结果由中断里的 `HAL_ADCEx_InjectedGetValue()` 直接读取。
> 通道 3/4 服务的是规则组，对应 `foc_math.c` 里 `ADC_Regular_Read_DMA()` 那条路径。

## 5. 中断向量与优先级

| 向量 | 处理内容 | 抢占优先级 |
|---|---|---|
| `ADC1_2_IRQn` | ADC 注入 JEOS → `MotorApp_OnInjectedConversion()`（25 kHz 控制） | 0 |
| `DMA1_Channel1_IRQn` | `HAL_DMA_IRQHandler(&hdma_usart1_rx)` | 0 |
| `DMA1_Channel2_IRQn` | `HAL_DMA_IRQHandler(&hdma_usart1_tx)` | 0 |
| `DMA1_Channel3_IRQn` | `HAL_DMA_IRQHandler(&hdma_adc1)` | 0 |
| `DMA1_Channel4_IRQn` | `HAL_DMA_IRQHandler(&hdma_adc2)` | 0 |
| `USART1_IRQn` | 串口错误与事件 | 0 |
| `TIM1_UP_TIM16_IRQn` | TIM1 更新（当前控制不依赖它） | 0 |
| `CORDIC_IRQn` | CORDIC 完成 | 0 |
| `FDCAN1_IT0_IRQn` | RX FIFO0 新报文 → `HAL_FDCAN_RxFifo0Callback()` | 2 |
| `FDCAN1_IT1_IRQn` | FDCAN 线状态/错误 | 2 |
| `TIM6_DAC_IRQn` | 1 ms 节拍 → `MotorProtocol_TimerTick()` | 3 |

> **同一抢占优先级的中断之间不能互相抢占。** 上面把 ADC、DMA、USART1、CORDIC 都放在 0，
> 意味着它们彼此只能顺序排队；FDCAN（2）可以被它们打断，TIM6（3）最低。
> 也就是说 25 kHz 控制中断**不会**被 CAN 接收或 1 ms 节拍打断——
> 这是"控制节拍优先"的有意设计。

## 7. 保留与未使用的资源

| 项 | 状态 |
|---|---|
| **GPIOF 时钟** | `MX_GPIO_Init()` 使能了 GPIOF 时钟，但**没有任何 PF 引脚被使用** |
| **TIM1_CH4 引脚** | 未配置，仅作内部 ADC 触发源 |
| **AS5600 / I²C** | 源码保留在 `Core/Src/AS5600.c`，但**未列入构建清单**，也没有 `hi2c1` 初始化；不能当作现有转速反馈 |
| **app_boot_control.c** | 在构建源清单里，但 `main()` 未调用其初始化与轮询；当前 Boot 命令由 `motor_protocol.c` 处理。**不要双重消费 FIFO0** |
| **ADC_Regular_Read_DMA()** | 保留接口，当前规则组不走这条路径 |
| **`foc_sin_cos`** | 预留的正余弦缓存，当前未使用 |
| **`Observer_State_t.pll_phase_`** | 预留角度补偿字段，当前观测流程未更新 |
| **UART FIFO** | `HAL_UARTEx_DisableFifoMode()`，显式关闭 |
| **FDCAN 自动重传** | 关闭 |
| **TIM1 刹车输入** | `BreakState` / `Break2State` 均关闭（无硬件刹车间断保护） |

> 最后一条值得注意：**当前没有配置 TIM1 的刹车（Break）功能**。
> 也就是说发生故障时功率级的关断完全由软件完成（`MotorApp_ForcePowerStageSafe()`、
> `FOC_PWM_Stop()`），没有独立的硬件刹车通道兜底。

## 8. 改引脚或外设时要同步什么

| 改动 | 必须同步 |
|---|---|
| 改 TIM1 的 ARR / 时钟树 | `MOTOR_APP_CONTROL_HZ`、`foc.timer.pwm_arr`、`foc.timer.adc_trigger`、所有毫秒阈值 |
| 改 ADC 注入通道 | `MOTOR_APP_ADC1_INJ_*` / `MOTOR_APP_ADC2_INJ_*`（否则上电自检拒绝启动） |
| 换电流采样电阻或放大网络 | `foc.current.gain_a/b/c`、以及[参数速查](10-参数与调参速查.md)里的量程推导 |
| 改串口波特率或引脚 | 上位机设置、`.vscode/tasks.json` 的 miniterm 任务 |
| 改 CAN 位定时 | 上位机、以及 `MOTOR_PROTOCOL_*` 的时间阈值（按 tick 计） |
| 改中断优先级 | 控制节拍的可抢占性；上面 §5 的结论会失效 |
| 给 CH4 分配引脚 | 会把内部触发源变成对外输出（一般不需要，且有风险） |
