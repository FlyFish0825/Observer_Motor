# 通信与调试：命令、帧格式和证据解释

> 本篇是当前接口的读写契约，不是自动执行脚本。网页工具只做本地解析/组帧，不连接串口或总线。所有示例均为说明，实际驱动前仍须确认板型、机械安全及限流。

## 1. 三条通信路径及执行域

```text
USART1 RX DMA/空闲事件 → 环形字节队列 → 主循环组行/解析 → 命令字段
FDCAN RX FIFO0中断   → 环形帧队列   → 主循环按ID/格式分派 → 命令字段
TIM6 1ms中断        → 节点时隙/调试分频 → 非阻塞尝试发送反馈
```

串口使用PB6/PB7、USART1、2,000,000 baud；FDCAN1使用PA11/PA12，仲裁/数据段均1Mbit/s，BRS关闭。接口成功只说明报文或变量被接受，实际启动需应用层门控与状态机。

来源：[`DebugConsole_Process()`](../Core/Src/debug_console.c#L323)、[`HAL_FDCAN_RxFifo0Callback()`](../Core/Src/motor_protocol.c#L488)、[`MotorProtocol_Process()`](../Core/Src/motor_protocol.c#L605)、[`MotorProtocol_TimerTick()`](../Core/Src/motor_protocol.c#L573)。

## 2. 文本命令：解析和确认的准确含义

命令以CR、LF或CRLF结束，支持退格。`set`要求名称和值，先检查类型、有限性/范围和只读属性，再写绑定地址并回显。变量名匹配忽略大小写；`#`在分词器识别的新token开始处表示其后是注释。不要假设支持shell式引号或任意转义。

```text
get just_float
set just_float 0
status
startdiag
```

这些是诊断准备命令；关闭JustFloat不停止控制，也不停止文本回复。`set wave_mode 0`只选波形布局，不是关闭输出。`OK run=on`只说明运行意图写入，不能当成达到闭环。

来源：[`DC_CommandSet()`](../Core/Src/debug_console.c#L609)、[`DC_Tokenize()`](../Core/Src/debug_console.c#L471)、[`MotorApp_RegisterDebugVariables()`](../Core/Src/motor_app.c#L1534)。

| 名称 | 读写 | 范围/单位 | 语义 |
|---|---|---|---|
| run | 写 | bool | 意图；0还用于解除故障闭锁 |
| speed | 写 | −15000～15000 rpm | 串口范围；0表示停机 |
| speed_en | 写 | bool | 速度模式请求；制动时应用可强制采用速度环 |
| speed_slew | 写 | 0～30000 rpm/s | 0冻结参考；运行条件减速可采用独立内部率 |
| speed_kp / speed_ki | 写 | 0～1 / 0～100 | 速度PI增益；范围不是稳定性保证 |
| id / iq | 写 | −8～8 / −10～10 A | 外部命令；启动和速度模式可采用不同参考 |
| just_float | 写 | bool | 波形总开关，上电默认0 |
| wave_mode | 写 | **0～4** | 新增4为回调耗时布局 |
| if_trim | 写 | bool | 可选I/f减流，默认0；不是通用失步修复 |
| vbus | 写 | 0～70 V | 危险诊断入口，会影响定标；规则采样还可能覆盖 |
| adc_chk | 写 | 0～1 | 自检门控；不建议绕过错误通道配置 |
| phase_u/v/w | 只读 | V | 实测三相端电压 |
| volt_src / volt_weight | 只读 | 0/1、0～1 | 来源选择和实际融合权重 |
| adc_cfg | 只读 | 0/1 | 注入配置自检结果 |
| ctrl_rad | 只读 | rad | 当前控制角 |
| rdy_fail / fail | 只读 | 位图 / 编号 | 即时Ready失败与整机故障原因 |

当前注册为22个变量、2条自定义命令（status、startdiag）；`DC_MAX_VARIABLES`是容量，不是已注册数量。运行请求与模式切换还要在控制域正式采用。来源：[`MotorApp_RegisterDebugVariables()`](../Core/Src/motor_app.c#L1534)。

## 4. status：每行是什么，不是什么

当前输出先打印最近`LOW_ENTER`快照（或no snapshot），随后打印各组动态字段。多行打印期间控制仍运行，因此不是一次冻结的整机快照。

| 分组 | 主要字段 | 解读 |
|---|---|---|
| STATUS | run/state/cal/MOE/rdy/fail | 实际许可、状态和故障；不是仅用户意图 |
| STATUS扩展 | rdy_fail/rdy_hist/rdy_count/rdy_max/span | 本拍位、验证历史并集、当前/最大连续计数、净角覆盖 |
| DRIVE | cmd/ref/rpm/rpm_f/speed_en | 用户目标、有效参考、原始/显示速度、本拍采用模式 |
| CURRENT | Iq_ref/Id/Iq/Ud/Uq/Ulim | 有效电流参考、反馈和电压额度 |
| CONTROL | rpm_fb/slew/if_accel/sat_d/sat_q/speed_aw/brake | 控制反馈、配置参考率、本段虚拟加速度、饱和与制动标记 |
| MOTION | segment/a_obs/if_rate/measured/iq_if/speed_i | I/f段号、观测派生加速度、继承率、来源标记、运行转矩和积分 |
| PWM | CCR/CCER/CR1 | 比较值与通道配置；不等于引脚实测波形 |
| OBSERVER | phase/flux/weight/U/V/W/ctrl/dtheta | 估计磁链角、幅值、融合、控制角差 |
| ADC | JDR1/JDR2/JSQR/adc_cfg | 该行主要是ADC2读回，用于确认Ib/V通道 |
| START | cmd_run/latched/phase/if_rpm/if_iq/dn/hold | 请求与闭锁、诊断子阶段、虚拟速度、匹配误差、总等待 |
| TIMING | dwt_cycles/max/time/max_time/budget/load/max_load/hclk | 回调周期数、微秒和占用率，未含完整IRQ开销 |

**当前dn = speed_rpm_f − 虚拟rpm**，不再等于原始speed_rpm−虚拟rpm。把if_rpm+dn作为原始转速会误读。`START if_iq`是按目标方向与幅值打印的辅助值；运行中实际参考优先看CURRENT.Iq_ref与MOTION.iq_if。

停机进入IDLE后观测器被复位，普通status中的phase/rpm可能已清零，而ctrl或dq电流保留旧值。此时dtheta不能作为故障前角差；故障前值要用锁存快照。来源：[`MotorApp_DebugStatus()`](../Core/Src/motor_app.c#L1441)、[`MotorApp_OnInjectedConversion()`](../Core/Src/motor_app.c#L1877)。

## 5. startdiag与LOW_ENTER：同一拍证据如何保存

`startdiag`按HANDOVER、CLOSED、FAULT打印。LOW_ENTER由status首先打印，记录运行中切入低速I/f的边界。每次捕获先清valid、写载荷、屏障、再置valid；打印前只在短临界区复制，耗时的格式化输出不占用该临界区。

| 快照 | 捕获位置 | 特别注意 |
|---|---|---|
| HANDOVER | 接管准备完成后，正式切state4之前 | state字段可以仍是3 |
| CLOSED | 首次实际执行闭环电流路径并准备输出后 | 已经过模式边沿与一次控制计算 |
| FAULT | 首次故障关MOE后、状态置IDLE之前 | 保留第一故障，不被后续守卫覆盖 |
| LOW_ENTER | 承接低速状态后、state设为3之前 | state可能还是1或4；结合segment理解 |

当前快照`mask`为 **即时位 OR 本验证段历史位**。而status.rdy_fail仍是即时位。不同版本日志的mask语义不同，不能把早期`mask=0`案例直接套到所有新日志。

新增字段`n_cmd,n_obs_f,rpm_fb,a_obs,if_accel,measured,segment,speed_i`用于区分目标、估计和衔接。`measured=1`表示使用观测速度派生的斜率，不表示装有独立机械加速度传感器。运行再入I/f会清后续HANDOVER/CLOSED快照准备新段，不能当作永远保存第一次启动。

来源：[`MotorApp_CaptureDiagnostic()`](../Core/Src/motor_app.c#L546)、[`MotorApp_PrintDiagnostic()`](../Core/Src/motor_app.c#L1392)、[`MotorApp_DebugStartup()`](../Core/Src/motor_app.c#L1422)、[`MotorApp_BeginForcedOpenLoop()`](../Core/Src/motor_app.c#L486)。

## 6. Ready位图与整机故障不是一张表

| 位 | 名称 | 当前检查 |
|---|---|---|
| 0x001 | PSI | 磁链幅值范围 |
| 0x002 | INIT | 已初始化 |
| 0x004 | SPEED | 原始速度绝对值≥800 rpm |
| 0x008 | DIR | 速度方向与PLL角步进方向 |
| 0x010 | ANGLE_STEP | PLL角单拍变化≤0.35 rad |
| 0x020 | SPEED_STEP | 原始速度单拍变化≤100 rpm |
| 0x040 | SYNC | 绝对角差检查，当前编译关闭 |
| 0x080 | TRACK | 电流误差/饱和连续2ms不合格 |
| 0x100 | SPEED_MATCH | 30Hz滤波速度与虚拟速度差≤40 rpm |
| 0x200 | DRIFT | PLL角差相对窗口锚点漂移≤1.0 rad |
| 0x400 | RAMP | 尚未进入高速I/f验证窗口 |
| 0x800 | NONFINITE | 检查输入非有限 |

全位为0只是本拍合格；Ready还要求连续750拍且净覆盖至少2π。历史并集只表示曾经出现过，不给出次数、时刻或持续长度。

整机fail：0无故障；1验证超时；2可选健康检查失败；3启动参数非法；4保留的方向变化码；5受计数门控的启动总超时；6关键数值非有限；7接管参考无效/反向转矩；8母线无效或调制定标失败。当前持续闭环健康检查关闭，不应因fail2存在就画成始终在监控。

来源：[`MotorApp_UpdateObserverReady()`](../Core/Src/motor_app.c#L800)、[`MotorApp_EnterFault()`](../Core/Src/motor_app.c#L586)。

## 7. JustFloat：布局、线速和时间解释

一帧32字节：7个小端float32，最后4字节`00 00 80 7F`。波形开关默认0。模式0尽力尝试发送；模式1～4每25拍尝试一次，串口忙时跳过，不等待新帧完成。

| mode | 通道1→7 |
|---:|---|
| 0 | Ia、Ib、Ic、rpm_f、phase_raw(deg)、Vbus、rpm原始 |
| 1 | phase、虚拟rpm、原始rpm、有效速度参考、ctrl−phase_raw、Iq_ref、观测坐标Iq |
| 2 | phase、Id_ref、Id、Iq_ref、Iq、Vbus、rdy_fail |
| 3 | rpm_fb、有效速度参考、Iq_ref、Iq、Ud、Uq、Ulim |
| **4** | 回调时间μs、周期数、最大μs、最大周期数、预算μs、当前占用%、最大占用% |

2Mbps且8N1时仅线传输32×10/2M=160μs，已大于40μs控制周期；不能声明模式0真实输出25kHz完整波形。加上软件调度与互斥后有效率还会更低。模式4发送上一回调已结算的计时数据，包含当时执行路径，仍不含完整IRQ进入/返回。

文本打印会暂时互斥波形，波形出现缺帧不必然意味着电流环丢拍。故障退出时图中phase还可能已切成IDLE，而数据来自之前一拍，边界分析需快照一起看。来源：[`MotorApp_SendJustFloat()`](../Core/Src/motor_app.c#L1606)、[`MotorApp_OnInjectedConversion()`](../Core/Src/motor_app.c#L1877)。

## 8. CAN ID、节点与格式

节点号1～8，速度槽索引node−1。发送ID基址加**节点号**，因此节点1反馈是0x201，节点8是0x208，不是0x200～0x207。标准11bit数据帧；格式和DLC必须同时匹配。

| ID | 格式 / 长度 | 用途 |
|---|---|---|
| 0x000 | Classic / 8 | APP管理、ENTER_BOOT |
| 0x100 | FD / 24 | 多节点控制向量 |
| 0x100 | Classic / 8 | 兼容旧单节点命令 |
| 0x180+node | Classic / 8 | Boot应答 |
| 0x200+node | FD / 12 | 普通反馈 |
| 0x280+node | Classic / 8 | 心跳 |
| 0x300+node | FD / 64 | 调试反馈 |
| 0x380+node | Classic / 8 | HELLO |

本地state=1才映射协议CLOSED_LOOP=2；其余本地阶段映射0。因此只看CAN状态0无法区分ALIGN、I/f、HANDOVER与真正IDLE，需要串口phase或扩展诊断。

来源：[`Core/Inc/motor_protocol.h`](../Core/Inc/motor_protocol.h#L1)、[`MotorProtocol_StateCode()`](../Core/Src/motor_protocol.c#L51)、[`MotorProtocol_HandleRx()`](../Core/Src/motor_protocol.c#L457)。

## 9. 24字节控制向量：位图和速度槽

| 字节 | 含义 |
|---|---|
| 0 | 协议版本，当前必须1 |
| 1 | 0x10速度向量、0x11启停向量、0x20调试选择、0x30单次反馈 |
| 2 | 节点选择位图；bit0=node1、bit7=node8 |
| 3 | 速度/启停命令为运行位图；调试选择用作使能标志 |
| 4～7 | 当前分支未使用，不扩展解释为CRC |
| 8～23 | 8个小端int16机械rpm，每节点2字节 |

**本帧没有应用层CRC8。** 0x10选中本节点后更新速度并请求速度模式；Byte3本节点位=1会请求run，但该位=0不会主动停止已有运行。0x11才按运行位图的0/1显式停止/启动。

0x20在普通目标位图检查之前处理：只允许一个调试位且使能非零；其他节点也会进入普通反馈抑制状态，选中节点发送调试帧。因此不能说“所有命令都先按Byte2排除非目标节点”。

当前速度向量解析已移除历史±10000软件门槛，接收范围由有符号int16字段决定。串口speed仍限定±15000；两条接口的语法边界不同，都不是可达速度/安全额定转速。来源：[`MotorProtocol_HandleVector()`](../Core/Src/motor_protocol.c#L382)。

## 10. Classic兼容与Boot控制

Classic 0x100：Byte0=node或0xFF；Byte1=0x01时Byte3为run，Byte1=0x02时Byte3～6为IEEE754 float速度；Byte7为前7字节CRC8。当前速度分支要求有限值，不再做历史±10000限制，写速度不等于启动。

Boot 0x000：Byte0目标、Byte1=0x04、Byte7 CRC8。只在Boot布局启用的有效路径中，应用请求停机、停止相关通信节拍、尝试有限等待应答、写TAMP备份魔数并复位。独立版不会因为同样帧就等价执行Boot跳转。

CRC8为多项式0x07、初值0、不反射、无最终异或，即x⁸+x²+x+1。不要与CAN外设链路CRC混为一谈。

来源：[`MotorProtocol_HandleLegacy()`](../Core/Src/motor_protocol.c#L437)、[`MotorProtocol_HandleBoot()`](../Core/Src/motor_protocol.c#L323)、[`MotorProtocol_CRC8()`](../Core/Src/motor_protocol.c#L103)。旧`AppBootControl_Process()`不在当前main运行路径内。

## 11. 反馈帧字节布局与量化损失

### 11.1 普通反馈，12字节FD

| 字节 | 类型/还原 | 含义 |
|---|---|---|
| 0～1 | int16，1rpm/LSB | speed_rpm_f |
| 2～3 | uint16 ×10/65535 A | 母线电流估算ibus_filter |
| 4～5 | uint16 /100 V | 母线电压 |
| 6～7 | uint16 ×170/65535 −20 ℃ | MCU温度 |
| 8 | uint8 | 协议状态，当前0或2 |
| 9 | bits | bit0校准、bit1请求速度环、bit2末端调制限幅 |
| 10 | uint8 | 反馈序号，回绕正常 |
| 11 | 保留 | 当前0 |

母线电流由软件功率估算，不是独立母线分流测量；有符号的回馈电流在uint16字段会被钳为0，因此仅凭该字段不能测量全部回馈能量。

### 11.2 调试反馈，64字节FD

Byte0～1为rpm_f；2～3电角速度；4/6/8为三相电流int16×100；10/12为Id/Iq×100；14/16为Ud/Uq×100；18为Vbus×100；20为温度int16×10；22为phase_raw度数×100；24状态、25校准、26速度模式、27调制限幅、28序号。未使用尾部保持0。16bit量化饱和会丢失超范围信息，不能当作浮点原值。

### 11.3 心跳与HELLO

心跳Byte0node、1状态、2校准、3调试使能、4为int8温度、5调制限幅、6序号、7CRC8。HELLO前5字节ASCII“HELLO”，Byte5node，Byte6固定1，Byte7CRC8。Boot应答与它们是不同帧，不能仅靠长度8判断类型。

来源：[`MotorProtocol_SendNormalFeedback()`](../Core/Src/motor_protocol.c#L238)、[`MotorProtocol_SendDebugFeedback()`](../Core/Src/motor_protocol.c#L270)、[`MotorProtocol_SendHeartbeat()`](../Core/Src/motor_protocol.c#L306)、[`MotorProtocol_SendPowerOnHello()`](../Core/Src/motor_protocol.c#L205)。

## 12. 队列、调度与丢帧

CAN RX中断将帧搬进8槽环形数组，head/tail留一个空槽用于判满，实际可待处理项少于数组长度。满时仍从硬件读出帧但丢弃，不推进head。主循环消费队列，不在接收IRQ里调速度控制器。

普通反馈按TIM6的10个1ms时隙分配，各节点通常每10ms尝试一次；调试独占模式按2ms节拍尝试，心跳主循环约1s。发送FIFO满返回忙，不能据此保证每周期必达。FDCAN配置关闭自动重传，主机应结合序号和超时识别丢失，但当前应用并未因此自动具备“通信丢失停机”功能。

来源：[`HAL_FDCAN_RxFifo0Callback()`](../Core/Src/motor_protocol.c#L488)、[`MotorProtocol_TimerTick()`](../Core/Src/motor_protocol.c#L573)、[`MotorProtocol_Send()`](../Core/Src/motor_protocol.c#L157)。

## 13. 一个故障案例应如何写报告

建议报告至少记录：固件构建/板型、命令前后顺序、供电与负载、status全文、startdiag全文、对应波形布局和时间范围。先确定是未开桥、I/f等待、接管拒绝还是闭环后退出，再解释原因。

例如“末拍rdy_fail=0而fail=1”只能说明超时时即时检查通过但持续资格没有形成；结合rdy_hist与rdy_max能缩小范围，仍不能由历史并集确定是哪一位出现次数最多。旧日志只保存末拍mask时更不应凭空补出丢失历史。

新版本诊断字段并不会自动证明上一版故障已解决。主机、源码与板上镜像不同步时，先核对版本，再比较阈值。

## 14. 台架命令顺序与停止后的保留证据

诊断准备时先`set just_float 0`，读取status确认配置；启动应由操作者在安全条件满足后单独执行，不把正反向启动串在一段无人监督脚本里。故障后先保存status/startdiag和波形，再考虑run0解除闭锁；复位或新启动会销毁部分现场。

网页组帧/解析工具没有任何硬件接口。复制一帧不等于已经发送；选择验证清单也只是本地记录，不代表台架验收自动通过。

### A. 四份可手工校验的报文

以下仅供离线字节解码。它们没有被发送到设备，不能连续复制到硬件工具后当作安全测试脚本。

**节点1速度目标1500，但不在本帧请求run。** ID `0x100`，FD/24字节。

```text
01 10 01 00 00 00 00 00 DC 05 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

Byte3为0不停止已有运行，也不在本帧发起新的run请求。Byte8/9=DC05，小端解码为1500。

**请求节点1单次状态。** ID `0x100`，FD/24字节。

```text
01 30 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

版本1、命令0x30、节点位图01。没有CRC8字段。

**旧版节点1浮点速度1500。** ID `0x100`，Classic/8字节。

```text
01 02 00 00 80 BB 44 85
```

Byte3～6为float32，小端00 80 BB 44；末字节是前7字节CRC8，不是速度的高字节。

**节点1心跳的合成例子。** ID `0x281`，Classic/8字节。

```text
01 02 01 00 19 00 07 62
```

这是软件构造的校验样例：状态2、已校准、温度25、序号7。并非从电机收到的真实心跳。

### B. 速度向量的停止语义为什么要读else分支

[`MotorProtocol_HandleVector()`](../Core/Src/motor_protocol.c#L382)

以下为当前实现的阅读摘录，移除注释与空行；省略外围内容时不改变原控制分支的含义。

```c
mask = data[2];
    uint8_t valid = ((debug_mask != 0U) &&
                     ((debug_mask & (uint8_t)(debug_mask - 1U)) == 0U) &&
                     (data[3] != 0U)) ? 1U : 0U;
    motor_protocol.debug_suppressed = valid;
    motor_protocol.debug_enabled =
        (valid != 0U &&
         (debug_mask & (uint8_t)(1U << (motor_protocol.node_id - 1U))) != 0U)
            ? 1U
            : 0U;
    motor_protocol.debug_divider = 0U;
    return;
  }
  mask = data[2];
  if ((mask == 0U) ||
      ((mask & (uint8_t)(1U << (motor_protocol.node_id - 1U))) == 0U)) {
    return;
  }
  index = (uint8_t)(motor_protocol.node_id - 1U);
  if ((data[1] == MOTOR_PROTOCOL_CMD_SPEED_VECTOR) ||
      (data[1] == MOTOR_PROTOCOL_CMD_RUN_VECTOR)) {
    if (data[1] == MOTOR_PROTOCOL_CMD_SPEED_VECTOR) {
      int16_t speed_rpm;
      memcpy(&speed_rpm, &data[8U + (2U * index)], sizeof(speed_rpm));
      motor_protocol.control->speed_command_rpm = (float)speed_rpm;
      motor_protocol.control->speed_ref_rpm = (float)speed_rpm;
      FOC_Control_EnableSpeedLoop(motor_protocol.control, 1U);
    }
    if ((data[3] & (uint8_t)(1U << index)) != 0U) {
      MotorProtocol_SetRun(1U);
    } else if (data[1] == MOTOR_PROTOCOL_CMD_RUN_VECTOR) {
      MotorProtocol_SetRun(0U);
    }
  } else if (data[1] == MOTOR_PROTOCOL_CMD_STATUS_ONCE) {
    MotorProtocol_SendNormalFeedback();
  }
}
```


观察Byte3本节点位为0时的else if：只有RUN_VECTOR主动调用SetRun(0)。对SPEED_VECTOR把这一步写成“run位决定全部启停”，会让主机误以为已经停止设备。停止命令应明确、可确认，不靠猜测速度更新帧的副作用。

### C. 快照发布到底保存了哪一种mask

[`MotorApp_CaptureDiagnostic()`](../Core/Src/motor_app.c#L546)

以下为当前实现的阅读摘录，移除注释与空行；省略外围内容时不改变原控制分支的含义。

```c
static void MotorApp_CaptureDiagnostic(MotorApp_Diagnostic_t *dst,
                                       MotorApp_Fail_t reason) {
  dst->valid = 0U;
  dst->tick = motor_adc_irq_count;
  dst->state = (uint32_t)foc_motor_state;
  dst->ready_fail = motor_ready_fail_mask | motor_ready_fail_history;
  dst->reason = reason;
  dst->direction = startup.if_direction;
  dst->virtual_rpm = (foc.observer.motor.pole_pairs != 0U)
      ? MotorApp_VirtualRpm() : 0.0f;
  dst->command_rpm = motor_control.speed_command_rpm;
  dst->observed_rpm = foc.observer.state.speed_rpm;
  dst->observed_rpm_f = foc.observer.state.speed_rpm_f;
  dst->reference_rpm = motor_control.speed_ref_active_rpm;
  dst->delta = FOC_WrapToPiFast(motor_control_angle_rad -
                              foc.observer.state.phase_raw);
  dst->id_ref = motor_control.reference.id_ref;
  dst->iq_ref = motor_control.iq_ref_active;
  dst->id = foc.state.i_dq.d;
  dst->iq = foc.state.i_dq.q;
  dst->vbus = foc.state.vbus;
  dst->segment = startup.segment;
  dst->control_rpm = foc.observer.state.speed_rpm_f;
  dst->accel_rpm_s = startup.measured_accel_rpm_s;
  dst->if_accel_rad_s2 = startup.if_accel_rad_s2;
  dst->speed_integral = motor_control.speed_pi.integral;
  dst->measured_ramp = startup.if_measured_ramp;
  __DMB();
  dst->valid = 1U;
}
```


`ready_fail`赋值有历史并集，和普通status逐拍rdy_fail不是同一口径。比较两次日志时，至少确认是否都含rdy_hist/n_obs_f/segment等新字段，不能把旧mask解释覆盖新版。

### D. 从现象建立最短证据链

| 现象 | 第一定位 | 第二定位 | 不应直接采取 |
|---|---|---|---|
| OK run后没有动作 | cal、adc_cfg、latched、state | 启动门控与母线 | 关闭全部保护 |
| 转到接管点后停止 | fail1与rdy_max/history | 信号/持续窗口，而不是仅末拍值 | 无限延长等待 |
| 接管期间停机 | state4、fail7/6、HANDOVER | qobs符号、数值与偏置 | 随意加π强行对齐 |
| 进入闭环后增速 | CLOSED快照、ref与Iq | q参考策略/速度PI边沿/参考斜坡 | 只给原始rpm做低通 |
| 反向命令后延迟 | brake、ref、speed_i | 进入低速的两个速度条件 | 仅按ref过零切换 |
| 回调占用突然增大 | TIMING、wave_mode4 | 同级IRQ、打印与分支路径 | 把耗时诊断放回阻塞中断打印 |

### E. 文本缓冲也有截断边界

`DebugConsole_Printf`使用固定长度发送缓冲，当前长STATUS/TIMING行加字段后应检查是否被截断。新字段在源码中存在，不等于每次都完整到达终端；若结尾持续缺失，先核对缓冲、实际串口字节和主机换行处理，再判定设备没有该变量。当前文档只指出验证目标，不擅自调整缓冲或协议。
