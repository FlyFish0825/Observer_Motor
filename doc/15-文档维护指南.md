# 文档维护指南（补充资料）

> 本文写给**以后要改这些文档的人**：文档分几层、新写一篇要登记到哪些地方、
> `doc/项目.html` 的内嵌快照怎么刷新、怎么验证没把网页改坏。
> 本文不涉及固件源码；改代码的流程见[测试与验证指南](12-测试与验证指南.md)。

---

## 1. 文档分层与编号约定

| 编号 | 定位 | 编号是否可复用 |
|---|---|---|
| `01`~`05` | 三层正文：大结构 / 中结构 / 小结构 | **不可复用**；层级变了要改的是内容，不是编号 |
| `06` | 开发记录（批次流水，按时间追加） | 不可复用 |
| `07`~`08` | 专题：施工计划、启动修正 | 不可复用 |
| `09`~`16` | 补充资料：按**使用场景**组织的工具型文档 | 不可复用，只追加 |
| `README.md` | 入口索引 | — |

约定：

1. **只追加编号，不重排。** 文档之间的相对链接大量使用编号，重排会一次打断很多链接。
2. **每篇开头用一段 `>` 引用写清"本文定位与不覆盖范围"**，并链到真正覆盖该内容的文档。
3. **每篇结尾给"相关文档"区块**，用相对路径链接，例如 `[控制层](02-控制层.md)`。
4. 表格优先于长段落；数值必须能在源码里找到出处，找不到就写「待人工核对」。
5. **不要写"本文档由 AI 生成"之类的元话语**，也不要写没有信息量的过渡句。

## 2. 新增一篇文档要登记的四处

少登记一处，就会出现"文件存在但没人找得到"的孤儿文档。四处都要改：

| # | 位置 | 改什么 |
|---|---|---|
| 1 | `README.md` → 「延伸文档（09~14）」表 | 加一行：我想… / 看这篇 / 内容 |
| 2 | `doc/01-系统架构总览.md` → §8.1「按用途查找」表 | 加一行用途与链接 |
| 3 | `doc/06-开发记录.md` → 「相关入口」列表 + 追一批批次记录 | 加链接，并写清本批改了什么 |
| 4 | `doc/项目.html` 的内嵌 `project-data` | 让新文档出现在网页的「项目文档」页（见 §4） |

如果新文档改变了"分层阅读"的结论（例如新增了第四层），还要同步 `01` 的 §8 表与 README 的「分层文档」表。

## 3. `doc/项目.html` 的结构

这个文件是**单文件离线手册**，约 5.0 MB。它不是普通网页，改动前必须先认清结构。

| 区域 | 位置特征 | 能不能手改 |
|---|---|---|
| `<style>` 样式块 | 文件开头到 `<body>` | 可以，但别动 CSS 变量名 |
| 侧边导航 `<nav class="nav">` | `<aside class="sidebar">` 内 | 可以（加 `data-page` 按钮） |
| 页面分区 | `<main class="content">` 内的 17 个 `<section class="page" id="page-…">` | 可以 |
| 页脚 | `<footer class="pagefooter">` | 可以 |
| 源码查看器弹窗 | `<div class="modal" id="sourceModal">` | 可以 |
| `source-highlight-data` | 一个 `<script type="application/json">`，约 3.7 MB | **生成物，不要手改** |
| `project-data` | 一个 `<script type="application/json">`，约 960 KB | 结构化数据，用脚本改（见 §4） |
| `startupHtml` | `project-data` 里的一个字符串字段，约 148 KB | 生成物，不要手改 |
| 主脚本 | 第一个无 id 的 `<script>`，以 `(()=>{'use strict';` 开头 | 可以，但风险最高 |
| 附加脚本 | 之后的无 id `<script>`（目前两个：文档检索层、CAN 帧工具） | 可自由扩展 |

### 3.1 页面与导航的绑定关系

页面切换完全由通用函数 `page(id)` 驱动，它只做三件事：

1. `document.querySelectorAll('.page')` 切换 `active` 类；
2. `document.querySelectorAll('.nav [data-page]')` 切换 `active` 类；
3. 面包屑取自 `.nav [data-page="…"]` 的 `textContent`，用 `replace(/^\d+\s*/,'')` 去掉序号。

**所以新增一个页面只需要两处**：一个 `<section class="page" id="page-X">`，和一个
`<button data-page="X"><span>NN</span>标题</button>`。不需要改 `page()`。

需要额外初始化逻辑时（本轮的术语表、参数表等），**不要改主脚本**，加一个独立的
`<script>` 块，用自己的 IIFE 和事件委托，避免与主脚本的全局状态互相影响。

### 3.2 页面里可用的样式与元素

| 类名 | 用途 |
|---|---|
| `.page` / `.panel` / `.grid2` | 页面容器 / 卡片 / 两列网格 |
| `.section-head` + `.eyebrow` | 带小标题的段落头 |
| `.note` / `.note.warn` / `.note.error` / `.note.info` | 提示块（`.info` 无独立样式，等同 `.note`） |
| `.table-wrap` + `<table>` | 带横向滚动的表格 |
| `.toolbar` / `.chip-row` / `.chip` | 工具栏 / 标签行 / 单个标签按钮 |
| `.metrics` | 四个数字卡片 |
| `.flow` + `.flow-step` + `.step-no` | 竖向流程线 |
| `.badge` / `.badge.active` / `.badge.legacy` | 小徽标（默认 / 绿色 / 橙色） |
| `.ref` | 可点击的符号/文件引用按钮 |
| `.empty` | 空结果占位 |

### 3.3 让内容能跳到源码

主脚本用事件委托处理点击，因此**只要给按钮加上 data 属性即可**，不需要绑定事件：

| 属性 | 效果 |
|---|---|
| `data-page="X"` | 切到 `page-X` |
| `data-fn="函数名"` | 在符号表里查同名函数，打开源码并定位 |
| `data-file="路径"` + `data-line="N"` | 打开该文件的第 N 行（路径须与 `project-data.files[].path` 完全一致） |
| `data-doc="路径"` | 在「项目文档」页渲染该 Markdown |
| `data-close="弹窗id"` | 关闭弹窗 |

`data-fn` 依赖静态符号表，**只在 `.c` 文件里定义的函数可被识别**；宏、`static inline`（在 `.h` 里）
和函数指针不会被匹配，这时改用 `data-file` + `data-line`。

## 4. 刷新内嵌快照（Markdown / 源码 / 高亮 / 符号行号）

`project-data.files[]` 里每一项都保存了 `text`、`bytes`、`lines`、`sha256`，
`source-highlight-data` 保存逐行高亮，`symbols` 保存函数定义行号。
**这些都不会自动跟随磁盘变化**，必须手工刷新。

### 4.1 需要重算的字段

| 字段 | 怎么算 |
|---|---|
| `path` | 相对仓库根的正斜杠路径，例如 `doc/10-参数与调参速查.md` |
| `name` | 文件名 |
| `ext` | 扩展名（Markdown 为 `.md`） |
| `bytes` | **UTF-8 字节数**（不是字符数） |
| `lines` | 按 `\n` 切分；末尾空行不算；`\r\n` 先归一化 |
| `sha256` | UTF-8 字节的 SHA-256（十六进制小写） |
| `text` | 原文（保留原始换行） |
| `symbols` / `macros` | Markdown 一律 `[]`；源码由生成器解析填充 |
| `compiled` | Markdown 一律 `false`；源码按 CMake 源清单判断 |

> 保持 `files[]` 的顺序：非 Markdown 文件按原顺序，Markdown 条目按
> README → `doc/01` → … → `doc/NN` 排列，因为网页的文档列表就是按这个顺序渲染的。

### 4.3 三份数据必须一起刷

这是最容易出事的地方：`project-data` 的 `text`、`source-highlight-data` 的高亮行、
以及 `symbols` 的行号**是同一批生成出来的**。只更新其中一个，网页就会出现
"用新行号显示旧代码"这类**比缺失更糟**的结果。

三条硬规则：

1. **改了 `.c` / `.h` → 三份都要刷。**
2. **改了 `.md` → 至少刷 `text`；若该文件的高亮条目还在，必须一起刷或删掉。**
3. **高亮行数必须与 `text` 行数完全相同**，否则查看器会逐行错位。

### 4.4 刷新流程

用一次性 Python 脚本完成，**不要手改那几个 MB 级的 JSON**：

```
A. 刷新 project-data.files[]
   1. 读出 doc/项目.html
   2. 正则取出 <script ... id="project-data"> 的内容并 json.loads
   3. 对每个条目按磁盘重算 text / bytes / lines / sha256
   4. 更新 generated / local_time
   5. json.dumps(ensure_ascii=False, separators=(",",":"))
   6. 把结果里的 "</" 替换成 "<\/"      ← 关键，见 §5.1
   7. 写回（UTF-8，newline=""）

B. 健康检查 source-highlight-data
   对 shell 条目逐个比较：
     len(entry["lines"]) == len(text 的行数)  且
     html.unescape(strip_tags(entry["lines"][i])) == text 的第 i 行
   不一致的条目：
     language == "C"        → 重新生成
     language == "Markdown" → 重新生成
     其它语言               → 删除该条目（查看器会回退为纯文本，见下）

C. 修正 symbols 的行号
   对改动过的文件，按函数名在新文本里重新定位：
     1. 找 `\b名字\s*\(`（跳过 . 与 -> 之后的形式，跳过注释/字符串里的匹配）
     2. 从该处配平括号，再看后面第一个非空白字符：
        是 `{` → 这是定义，用花括号配平得到 end
        是 `;` → 这是声明，end = line
     3. line/end 用偏移量换算成行号
     4. calls 在函数体内扫 `\b标识符\s*\(`，排除关键字与自身
```

### 4.5 为什么高亮可以删、不能凑

`renderSource()` 取高亮的方式是：

```js
const content = highlighted?.lines[first + i] ?? esc(text);
```

也就是说：**条目不存在时**用真实文本（正确，只是没有配色）；
**条目存在但行数或内容不符时**，它会优先显示那条错误的高亮行（显示错误代码）。

所以遇到"无法可靠重生成高亮的语言"（汇编、链接脚本、CMake…），
**正确做法是删掉那个条目让它回退**，而不是保留旧数据。

### 4.6 字符级安全不变量

重新生成任何高亮时，必须逐行验证：

```
html.unescape(去掉所有 HTML 标签(高亮行)) == 原始行
```

这条不变量成立就意味着：无论配色对不对，查看器显示的**字符**一定正确。
本轮刷新 5 个 C 文件时，19536 行全部满足该不变量（0 处不符）。

### 4.7 新增页面时注意

导航序号是**手工维护**的（`<span>13</span>` 之类）。加页时：

- 新页的 `<span>` 序号要接在最大序号之后；
- 新页的 `<section>` 插在 `<main class="content">` 内、`<footer class="pagefooter">` **之前**；
- 新页若需要脚本，**另起一个 `<script>` 块**，不要塞进已有脚本里。

## 5. 已知的坑

### 5.1 JSON 里的 `</`

HTML 规范规定：`<script>` 元素内容中一旦出现 `</script`（大小写不敏感），元素就结束。
如果某段源码或注释里恰好含这个序列，JSON 会被截断，整个网页报废。

**处理**：序列化后统一把 `</` 替换成 `<\/`。在 JSON 字符串里 `\/` 与 `/` 等价，解析结果不变，
但 HTML 不再提前结束脚本。同理不要在 `<script>` 里写 `<!--`。

### 5.2 PowerShell 回写会毁掉 UTF-8 文件

本轮实测的一次真实事故：用

~~~powershell
$c = Get-Content $f -Raw
$c = $c -replace 'x','y'
Set-Content $f -Value $c -Encoding UTF8 -NoNewline
~~~

处理一个含中文与全角标点的 UTF-8 文件时，中文被按错误的代码页解码后再编码，
**文件变成双重编码的乱码，且部分字符已经丢失（变成 `?`），无法逆向恢复**。

规则：

- **不要**用 `Get-Content` / `Set-Content`（或 `Out-File`）读写含非 ASCII 内容的项目文件；
- 要读，用能显式指定编码的方式并确认输出；
- 要改，**优先用编辑工具做定点替换**，或用 Python 的 `io.open(..., encoding="utf-8", newline="")`；
- 一旦发现乱码，不要试图"再替换回去"，直接从备份恢复并重做。

### 5.3 控制台编码造成的"假故障"

在本机终端里 `Get-Content` 一个正常的 UTF-8 中文文件，**可能显示成乱码而文件本身是好的**。
判断文件是否真的坏了，要换个能正确解码的方式看（例如编辑器或读取工具），
**不要**因为终端显示乱码就去"修复"文件。

### 5.4 编号与锚点

- 新增页面后，导航序号数组必须仍然递增（可用脚本核对）。
- Markdown 里指向中文小节的锚点很脆：标题里带 `（）`、`/`、`` ` `` 时，各渲染器的
  slug 规则不完全一致。**跨文件链接优先只链到文件**，把小节号写成正文里的「见 §4.2」，
  比赌锚点更稳。
- 表格单元里出现裸 `|`（例如写绝对值 `|Id|`）会撕裂表格。要么转义成 `\|`，
  要么改写成「Id 绝对值」。

## 6. 改完怎么验证

四条自查，全部通过才算改完。

### 6.1 Markdown 结构自检

检查项：表格各行列数是否与表头一致、表格单元里的内联代码是否含裸 `|`、
相对 `.md` 链接的目标是否存在、锚点是否能在目标文件里找到。

思路（可用任意脚本实现）：

```
逐行扫描，识别 "以 | 开头且下一行是分隔行" 的表头 → 统计本块每行的单元数并比对；
对每行，找出所有 `…` 内联代码，若含 '|' 且不含 '\|' 则报错；
对每个 [文字](目标)，若目标含 '#' 则拆出文件名与锚点，
  文件名用 os.path.normpath 相对当前文件解析并检查存在性，
  锚点转成 slug 后在目标文件的标题集合里查找。
```

> 注意：判断表格单元时要**先按未转义的 `|` 切分**，否则 `\|` 会被误判成列分隔符。

### 6.2 JSON 块可解析

`source-highlight-data` 与 `project-data` 两块都要能 `json.loads`。

### 6.3 页面与导航一致性

- `<section class="page" id="page-X">` 的数量 == 导航按钮数量；
- 每个 `data-page` 目标都存在于页面集合里；
- 页面 id 唯一；导航序号严格递增。

> 扫描时要**先把 `<script>…</script>` 整段剔掉**：主脚本里有一个
> `` `.nav [data-page="${id}"]` `` 模板字符串，会被朴素的字符串扫描误当成页面引用。

### 6.4 新增脚本的语法与运行

1. 抽出每个 `<script>` 的内容，用 `node --check` 验语法；
2. 在 Node 里用一个最小 DOM 桩（`document.getElementById` 返回带
   `innerHTML` / `textContent` / `value` / `checked` / `addEventListener` 的假元素，
   并提供 `localStorage`、`location`、`history`）跑一遍真实脚本，确认初始化不抛异常、
   各渲染函数确实写入了内容。这一步能抓到大部分"下标越界 / 未定义属性 / 事件绑定错元素"的问题，
   比肉眼读代码可靠得多。

**主脚本也要这么测**（它是最容易被忽略的一个）：把 `project-data` 与
`source-highlight-data` 的真实 JSON 喂给桩里的对应元素，脚本就会执行完整的启动流程
（写 `fileCount`、构建文档列表、渲染模块卡与目录树、切换页面）。可以顺带断言
`window.__portalQA` 里的文件数、符号数和页面数。

> 桩里要给输入控件**预置**与页面 `value="…"` 相同的初始值，否则文本框读到的空串会让
> 换算器输出全为 0，看起来像功能坏了。另外 `document.querySelectorAll('.page')`
> 与 `querySelector('.nav [data-page=…]')` 也要返回像样的东西，
> 否则页面计数为 0、面包屑只剩页面 id。

### 6.5 跳转目标要单独查

`data-fn` / `data-file` / `data-line` 写错时**不会报错**，只会静默显示占位文案：

| 属性 | 写错的后果 | 怎么查 |
|---|---|---|
| `data-fn="X"` | 显示"静态索引未识别此函数" | 把所有 `data-fn` 取出来，逐个到 `symbols[].name` 里找 |
| `data-file="P"` | 显示"快照中没有该文件" | 逐个到 `files[].path` 里找（**注意 `tests/`、`tools/` 默认不在清单里**） |
| `data-file` + `data-line="N"` | 打开到错误位置 | `1 <= N <= files[P].lines` |

交互页里由 JS 在运行时拼出的按钮（例如参数表、术语表）也要查：
从页面的脚本块里把 `file, line` 两个参数抽出来，同样按上面的范围校验。
本轮 113 条参数与 94 条术语链接全部通过。

> 扫描时同样要先剔掉 `<script>…</script>`，否则脚本里的模板字符串会被误当成 HTML 属性。

### 6.6 两个"一次覆盖全库"的扫描

比起逐篇目视，下面两种扫描能一次找出所有陈旧引用，建议每次改完文档都跑：

**① 函数名扫描**
把每篇里形如 `Xxx_Yyy(` 的标识符抽出来，逐个到 `symbols[].name` 里查。
为了避免把"有意记录的历史名"误报，需要允许两种豁免：
- 名字在一个显式白名单里（例如 `MotorProtocol_PollRx`）；
- **同一行或上两行出现**"不存在 / 已不 / 已被 / 旧版 / 历史 / 取代 / 残留 / 已移除 / 过期"这类标记词。

**② 宏名扫描**
先从 `Core/` 下所有 `.c/.h` 收集 `#define NAME` 与枚举成员名，再扫文档里的全大写标识符
（前缀限定为项目自己的命名空间），把不在集合里的报出来。

两个扫描的常见假阳性，报出来时要用上下文人工过一遍：

| 假阳性 | 原因 |
|---|---|
| `MOTOR_APP_FAIL_*`、`MOTOR_PROTOCOL_ID_*_BASE` | 文档里用的是通配前缀，不是完整宏名 |
| `OBSERVER_NOT_READY`、`OBSERVER_HANDOVER` | 省略了前缀，实际是 `MOTOR_APP_FAIL_OBSERVER_NOT_READY`、`FOC_MOTOR_OBSERVER_HANDOVER` |
| 枚举的**最后一个**成员（无尾逗号） | 采集正则要求后随 `=`、`,` 或 `}`，会漏掉 |
| HAL/CMSIS 的常量 | 属于 SDK，不在项目定义集合里 |

本轮据此定位并修掉了 4 个不存在的启动宏、1 处 `DRIFT_RAD` 数值错误与
1 处与硬件事实相反的时序描述。

### 7.1 顺带发现并订正的事实错误

自查过程同时也是源码核对过程，本轮据此订正了下列**与源码不符**的描述
（明细见[开发记录](06-开发记录.md)第六~九批）：

- `MotorProtocol_PollRx()`、`MotorProtocol_RunScheduler()`、`MotorApp_ResetIdle()`、
  `MotorApp_StartClosedLoop()`、`MotorApp_RunClosedLoop()`、
  `MotorApp_UpdateObserverVoltage()`、`MotorApp_CalibrateAnalogFrontEnd()`、
  `MotorApp_JustFloatInit()`、`BoardAdc_GetSnapshot()` —— **这些函数都不存在**。
- `board_adc.c` **没有 seqlock**：没有序号、没有读端、没有超时判据。
- ADC 电流通道引脚：Ia = **PA2**、Ic = **PB1**、Ib = **PA6**（原写 PA1/PA2/PC1）。
- OPAMP 是 `STANDALONE` 模式且 `InternalOutput = DISABLE`，×24 增益来自**外部电阻网络**。
- `FOC_VOLTAGE_UTILIZATION_DEFAULT` = **1.0**（原写 0.98，源码已明确不扣 2% 裕量）。
- 周期反馈帧 Byte 2-3 是**母线电流估算**不是 Iq；Byte 6-7 是**带偏置的温度**不是保留位。
- 调试反馈帧 Byte 20-21 是**温度**；心跳帧 Byte 4 是 **int8 温度**。
- JustFloat 帧是 **7 通道 32 字节**（原写 6 通道 28 字节）。
- `status` 输出是 **9 行**，字段已按当前实现重列；`dn` 是**转速偏差**不是方向。
- `phase` 码里**没有 11**；实际是 12/33/32/31/30/10 + 原始枚举 0/1/2/3/4。
- 中断优先级不是"其余默认"：除 FDCAN(2)、TIM6(3) 外全部是抢占优先级 0，
  同级之间**不能互相抢占**。
