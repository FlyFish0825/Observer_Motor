# 底层参考：接口契约、状态对象与源码索引

> 本篇按“能从哪个执行域调用、读写哪些状态、错误如何退出”组织，而不是只罗列函数名字。附录函数区间与签名从本次文本定义生成，包含静态/内联/条件编译分支；不等于链接后可执行符号清单。

## 1. 使用这份参考的方式

先确定问题属于采样、估计、控制、状态交接还是通信，再看该模块的契约。签名给类型和参数，契约给执行域和副作用，源码链接给当前行号。静态调用候选只按函数名识别，宏、回调、同名函数和条件编译需人工核对。

网页中的测试文件若标为“历史快照”，表示当前磁盘未找到，不能当作已存在的回归入口。正式代码、保留源码、历史快照三类必须分开。

## 2. 数据对象与唯一所有者

| 对象 | 类型/所有者 | 典型字段与风险 |
|---|---|---|
| foc | FOC_Handle_t，全局唯一 | 采样、变换、电压、PWM和观测器；不是一个原子快照 |
| motor_control | FOC_Control_t，motor_app内部 | 三个PI、命令/采用参考/反馈，控制域维护运行历史 |
| startup | MotorApp_Startup_t，应用状态机 | 冷启动、Ready、接管、低速段号与斜率；不直接公开为协议结构 |
| voltage_source | MotorApp_VoltageSource_t | measured_selected与measured_weight，两者收敛时刻不同 |
| board_adc_measurements | BoardAdcMeasurements_t | 母线/温度结果，仅规则组；没有seqlock |
| motor_*_snapshot | MotorApp_Diagnostic_t | HANDOVER/CLOSED/FAULT/LOW_ENTER事件快照 |
| foc_sin_cos | FOC_SIN_COS_t | 当前控制角的正余弦，Park与逆Park实际使用 |
| observer_sin_cos | FOC_SIN_COS_t | PLL鉴相使用，不是电流Park的替代缓存 |

来源：[`Core/Inc/foc_math.h`](../Core/Inc/foc_math.h#L1)、[`Core/Inc/controller.h`](../Core/Inc/controller.h#L1)、[`Core/Src/motor_app.c`](../Core/Src/motor_app.c#L1)。

## 3. 类型、单位和控制状态

ABC/AlphaBeta/DQ只是坐标容器，本身不携带单位和参考系标签。调用者必须说明其中存的是A还是V、是虚拟dq还是观测dq。尤其iq_ref_active的坐标随控制角选择而变，不能跨阶段不经变换就拿来解释转矩。

`FOC_Motor_State_t`当前包含IDLE=0、CLOSED=1、ALIGN=2、IF=3、HANDOVER=4。协议映射仅输出0或2；诊断phase还可能10/12/30/31/32/33。三个编号空间不可相互代用。

## 6. 关键字段的生命周期与陷阱

| 字段组 | 新启动 | 正常运行 | 低速重入/故障 |
|---|---|---|---|
| ready_count / span | 重置 | Ready窗口逐拍更新 | 任何失败清零；新目标/新段也清 |
| ready_max_count / history | 新窗口清 | 记录最长连续与曾出现位 | 不是发生频次或全运行累计 |
| if_angle / signed speed | 定位后从0开始 | 低速/换向用连续轨迹 | 运行入口承接当前角/速度，不清零 |
| measured_accel / samples | 尚无有效样本 | 可信闭环区估计 | IF期间冻结，不使用盲区虚拟速度反算“实测” |
| speed_ref_rpm | 应用内部目标 | 可与用户cmd不同 | 高速反转段内部向0制动 |
| speed_ref_active_rpm | 控制器内部状态 | 每拍斜坡采用值 | speed模式边沿以反馈播种；50ms保持 |
| iq_ref_target / active | 从命令或启动阶段建立 | 目标1kHz更新/采用值25kHz限速 | 坐标接管与运行入口不能盲目清零 |
| valid / segment | 清快照/初始化段号 | 按事件捕获 | LOW_ENTER关联最近运行I/f段 |

`FOC_Control_Reset`保留用户配置不表示所有参考历史均保持；以函数中的赋值逐项核对。修改结构体字段必须同步初始化、复位、诊断、测试替身及文档，不能只改typedef。

## 7. 失败传播与返回值契约

HAL型函数以返回值表示是否完成某项配置或计算；应用控制函数多为void，但可能内部调用EnterFault并改state。因此“函数返回”不等于“仍可驱动”。调用者须在观测后、参考计算后、调制后、写CCR前按现有路径检查状态和有限性。

| 故障/拒绝 | 处理入口 | 后续条件 |
|---|---|---|
| 零偏未完成 | OnInjected校准分支返回 | 主循环门控继续等待 |
| ADC注入布局不匹配 | Init记录cfg=0 | 默认拒绝run，不需要把整个控制台卡死 |
| 无效母线/非有限输入 | EnterFault | 立即撤MOE，锁存首故障 |
| Ready不合格 | UpdateObserverReady | 清连续资格；验证超时才fail1 |
| 接管obs系q方向错误 | BeginObserverHandover | fail7，不能再把state写成HANDOVER |
| 辅助观测失效 | RecoverAuxObserver（IF限定） | 清Ready继续虚拟控制；依赖观测状态仍应退出 |
| 规则组超时 | BoardAdc_Update | 停规则转换、保持旧结果；主循环可重试 |
| 发送FIFO忙 | MotorProtocol_Send | 本次未提交；不阻塞等待无限重发 |

## 8. 编译布局与底层资源契约

正式16MHz板：HSE16/M4×N85/R2=170MHz；24MHz测试变体M6，其余倍分频相同。VCO为340MHz而非170MHz。链接地址与VTOR必须一致：standalone为0x08000000，boot为0x08005000。Boot版保留末尾配置区；不能混用镜像与地址。

`AS5600`需要I2C依赖但未纳入当前固件；`app_boot_control.c`保留旧接口，当前Boot请求由motor_protocol处理。`ADC_Regular_Read_DMA`是保留接口，不能与BoardAdc轮询同时消费同一规则序列。系统调用桩、向量表和厂商初始化模板与应用主链分别看。

## 11. 查找不到函数时怎么处理

先搜索当前名称与调用点，再检查它是宏、静态内联、厂商函数、仅声明、条件编译分支还是已合并到别的函数。历史MotorApp_ResetIdle、MotorApp_JustFloatInit、MotorApp_UpdateObserverVoltage等名称不应继续画成现行独立调用；目前对应逻辑已并入现存入口。

符号表不解决函数指针调用图；静态函数同名也可能来自不同文件。源码快照与磁盘时间不一致时先刷新，不能靠移动行号“修好”旧代码。
