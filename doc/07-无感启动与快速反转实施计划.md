# 无感启动、飞车接管与快速反转实施计划

> 本文是后续启动与换向改造的唯一施工顺序基线。目标不是一次完成全部功能，而是在现有 FOC、电流 PI、SVPWM、磁链观测器基础上，按风险从低到高逐步增加能力。
>
> 核心原则：**一次只实施一个步骤；每一步都必须能够单独编译、单独验证、单独回退；当前一步没有验收通过，不进入下一步。**

## 1. 总体目标

最终形成以下运行路径：

~~~text
IDLE / 待机侦测
├─ BEMF 可信、同方向  -> FLYING_CATCH -> CLOSED_LOOP
├─ BEMF 可信、反方向  -> FLYING_CATCH -> REV_BRAKE -> ...
└─ BEMF 不可信        -> ALIGN -> I/F -> OBS_HANDOVER -> CLOSED_LOOP

CLOSED_LOOP
└─ 收到反向命令 -> REV_BRAKE -> REV_PREDICT -> REV_HANDOVER -> CLOSED_LOOP
~~~

第一版继续保留：

- 现有 FOC 电流环。
- 现有 Park / 逆 Park。
- 现有 SVPWM。
- 现有磁链观测器与 PLL。
- 现有 ADC、电流采样和端电压采样框架。

第一版明确不做：

- 不引入六步换向作为主启动方案。
- 不引入未经验证的 HFI / IPD。
- 不一次性重构 controller、observer、motor_app。
- 不同时修改启动、飞车、快速反转和电压融合。
- 不为了“顺手优化”修改与当前步骤无关的代码。

---

## 2. 施工规则

### 2.1 每一步固定流程

以后严格按下面流程执行：

1. 先确认当前 Git 状态，明确本步骤允许修改的文件。
2. 只实现本文当前步骤，不提前实现后续功能。
3. 保持改动最小，不复制现有功能，不建立无必要的新封装。
4. 编译 Debug；必要时再编译 Boot-Release。
5. 做静态检查，确认状态机、PWM 关断、参考值来源没有破坏原行为。
6. 如该步骤需要上电，再单独做串口 / CAN / 波形验证。
7. 验收通过后再提交 Git，提交信息使用中文并写清步骤号。
8. 在本文“实施记录”中记录提交号、测试结果和遗留问题。
9. 当前步骤没有通过，不开始下一步。

### 2.2 回退原则

每一步都必须有明确回退点：

- 一个步骤尽量对应一个独立 Git 提交。
- 不把两个不同风险等级的功能塞进一个提交。
- 如果实机结果异常，优先回退到上一个已验收提交，而不是继续堆补丁。

### 2.3 参数原则

以下参数都先作为“可标定参数”，不能直接写成物理保证：

- ALIGN 电流。
- ALIGN 持续时间。
- I/f 启动电流。
- I/f 加速度。
- ObserverReady 阈值。
- 交接时间。
- 快速制动电流。
- 预测穿零最长时间。
- 反向重新接管阈值。

软件中的 ±10 A 限幅不等于电机允许峰值电流，也不等于快速制动时允许的回馈电流。

# 3. 第一阶段：先整理控制权，不改变现有控制算法

这一阶段风险最低，先把后面所有状态需要的“控制权”理顺。

## Step 1：明确角度、Id、Iq、速度环的唯一来源

**难度：低**

**目的：**

解决后续状态增加后多个模块同时写 `phase_raw`、`id_ref`、`iq_ref`、速度 PI 输出互相覆盖的问题。

**本步骤只做：**

- 梳理当前控制中断内角度来源。
- 梳理 Id / Iq 参考来源。
- 梳理速度 PI 何时覆盖 `iq_ref`。
- 建立一个明确的“控制参考仲裁”位置。
- 保持当前正常闭环运行行为不变。

可以形成类似概念：

~~~c
typedef struct
{
    float theta_ctrl;
    float id_ref;
    float iq_ref;
    uint8_t speed_loop_enable;
} MotorControlRef_t;
~~~

最终名称以现有代码风格为准，不强制照抄。

**禁止：**

- 不增加 ALIGN。
- 不增加 I/f。
- 不改 observer 算法。
- 不改电压融合。
- 不改 PWM 时序。
- 不改快速反转。

**预计主要文件：**

- `Core/Src/motor_app.c`
- `Core/Src/controller.c`
- 必要时对应头文件。

**验收：**

- 当前 RUN 行为与修改前一致。
- 当前 CLOSED_LOOP 的 Park 角仍来自原有有效角。
- 速度环打开时行为不变。
- 速度环关闭时，直接 Iq 参考不会再被旧速度 PI 输出意外覆盖。
- 停机仍能在下一控制周期安全关桥。
- Debug 编译通过。

---

## Step 2：让控制中断允许“非 CLOSED_LOOP 的受控状态”

**难度：低**

**目的：**

当前 ISR 如果不是闭环状态就会进入 IDLE / 清理路径，后续 ALIGN、I/f、交接状态无法真正运行。本步骤只解除这个结构限制。

**本步骤只做：**

- 把“是否执行电流采样和 FOC”的条件，从“必须 CLOSED_LOOP”改为“当前状态是否属于主动控制状态”。
- 保留 IDLE / STOP 的安全关桥逻辑。
- 暂时可以只有 CLOSED_LOOP 被定义为主动控制状态，先把结构搭好。

**禁止：**

- 还不真正增加 ALIGN 控制动作。
- 不改变正常闭环输出。

**验收：**

- 功率桥上电默认仍关闭。
- IDLE 不会误进入 SVPWM 输出。
- CLOSED_LOOP 行为与原来一致。
- 后续新增主动状态时不需要再次大改 ISR 主结构。

---

# 4. 第二阶段：先完成静止启动

这部分先解决“电机静止时如何可靠起来”，暂时不做飞车和快速反转。

## Step 3：增加 ALIGN 状态，但只做受限定位

**难度：中低**

**状态：**

~~~text
IDLE -> ALIGN -> 暂时退出 / 停机
~~~

第一轮先不要立刻接 I/f，先单独把 ALIGN 做对。

**本步骤实现：**

- ALIGN 专用控制角。
- 定位电流缓升。
- 优先采用两个相邻定位角，或一个很小的受控角度移动后停在最终定位角。
- 定位完成条件按时间管理。
- 定位期间速度 PI 关闭，只运行电流环。

**初始调试原则：**

- 总定位过程先预留约 20～40 ms 的调试范围。
- 不把 5～10 ms 当作先验保证。
- 电流先从保守值开始，后续根据实机结果标定。

**失败 / 停止：**

任何 STOP、故障或保护条件出现，都立即退出 ALIGN 并安全关桥。

**验收：**

- 不同初始转子位置都不会出现不可控的大电流冲击。
- 定位角控制连续。
- Id / Iq 和 PI 没有被速度环覆盖。
- STOP 能立即退出。
- 暂时不要求自动旋转起来。

---

## Step 4：增加独立 I/f 开环启动

**难度：中**

**状态：**

~~~text
IDLE -> ALIGN -> OPEN_LOOP_IF
~~~

先只验证电机能被稳定拖起来，暂时不交给 observer。

**本步骤实现：**

- 从 ALIGN 最终角平滑进入虚拟角。
- 虚拟角积分：

`theta_v[k+1] = theta_v[k] + omega_v[k] * Ts`

- 逐步撤掉定位所需 Id。
- 建立目标方向 Iq。
- 按受限加速度增加虚拟电角速度。
- 全程继续使用现有 dq 电流 PI 和 SVPWM。
- 设置启动最高检查速度，第一轮以约 1000 rpm 作为上限 / 检查点，不代表强制交接点。

**禁止：**

- 不以 observer 速度强行覆盖虚拟角。
- 不到 1000 rpm 就自动宣布启动成功。
- 不在本步骤做自动 observer 接管。

**验收：**

- 正方向能从静止稳定加速。
- 反方向也能独立验证。
- 电流跟踪正常，无持续饱和。
- 虚拟角连续，无跳变。
- 到设定检查速度后可以安全保持短时验证或退出。

---

## Step 5：建立第一版 ObserverReady 判据

**难度：中**

本步骤只做“判断”，暂时不切控制角。

**原则：**

不能只用一个转速阈值，也不能使用不存在的“真实角度误差”。

第一版建议组合以下已有信息：

- BEMF / 磁链幅值达到最小可观测范围。
- 磁链幅值没有持续异常。
- `phase_raw` 连续。
- observer 速度方向与启动方向一致。
- observer 速度没有异常跳变。
- PLL 相位残差在动态工况允许范围内。
- 电流跟踪没有持续失控。
- 没有持续电压饱和。
- observer 与虚拟角的相对角差没有持续失控增长。
- 条件连续成立一段时间。

第一轮验证窗口可从：

- 连续约 3～5 ms。
- 同时覆盖至少约 60° 电角度。

开始标定。

**注意：**

当前 PLL 在快速加速时本身可能存在明显相位滞后，因此不能机械使用“PLL 相差必须 < 10°”作为固定门槛。

**验收：**

- 串口能观察 ready 组成条件。
- I/f 正常同步时能稳定进入 ready。
- 明显失步 / 电流饱和时不能误报 ready。
- ready 抖动应有进入 / 退出滞回或持续时间约束。

---

## Step 6：实现 I/f -> Observer 平滑接管

**难度：中高**

这是静止启动阶段的最后一步。

**控制角：**

先计算：

`delta = wrap(theta_virtual - theta_observer)`

使用：

`theta_control = theta_observer + delta_blend`

然后平滑让 `delta_blend -> 0`。

**同时必须处理：**

- 控制角连续。
- Id / Iq 参考连续。
- dq 坐标变化时 PI 积分状态不能造成电压矢量跳变。
- 交接期间保持电流模式。
- 完成角度接管后，再以当前速度初始化速度参考。
- 速度 PI 根据当前有效 Iq 进行无扰预装，然后恢复正常速度控制。

**交接条件：**

- ObserverReady 已持续成立。
- 角差仍在可处理范围。
- 电流和电压有足够裕量。

**验收：**

- 接管瞬间三相电流无明显尖峰。
- `theta_control` 连续。
- dq 电流没有因坐标切换突然旋转。
- 速度环重新投入时 Iq 不跳变。
- 正反方向静止启动都通过。

**完成 Step 6 后，先冻结并长期验证静止启动。**

在这一阶段稳定以前，不进入飞车和快反转。

---

# 5. 第三阶段：待机 BEMF 与飞车启动

## Step 7：IDLE 增加关桥 BEMF 侦测

**难度：中**

**前提：**

功率桥关闭，并确认相电流已经充分衰减。

**维护：**

~~~text
bemf_angle
bemf_speed
bemf_direction
bemf_magnitude
bemf_confidence
bemf_update_time
~~~

使用三相端电压去共模后的 αβ 电压矢量，结合 RC 相位补偿和实际处理延迟估算反电势角；过零顺序用于交叉检查。

**注意：**

- BEMF 很弱只能说明运动信息不足，不能证明绝对静止。
- 必须检查端电压削顶、整流失真和噪声。
- 初期只做检测和日志，不自动接管。

**验收：**

用外部方式带动电机时：

- 正反方向判断正确。
- rpm 与独立基准基本一致。
- 电压角连续。
- 低于可观测阈值时 confidence 正确下降。

---

## Step 8：同方向 Flying Catch

**难度：中高**

**路径：**

~~~text
IDLE
-> BEMF 可信且与命令同方向
-> 用 BEMF 角 / 速度初始化
-> 小 Iq 同步接住
-> ObserverReady
-> 正常闭环
~~~

**本步骤只做同方向。**

反方向带转先不自动反转，避免一次引入两个难题。

**验收：**

- 多个初始转速下均可接住。
- 接管时电流冲击受控。
- 不出现角度跳 180° / 相序错误。
- 低可信度时自动退回静止启动路径，而不是强接。

---

## Step 9：反方向 Flying Catch，只做到“接住”

**难度：中高**

**路径：**

~~~text
IDLE
-> 检测到反方向带转
-> 按实际方向同步接住
-> 进入受控 CLOSED_LOOP
~~~

本步骤仍不做快速反转。

目的是先确认：

> 软件能够承认并稳定控制“当前实际旋转方向”。

**验收：**

- 正命令下遇到反向带转，不会直接施加错误角度的大转矩。
- 先完成同步，再等待下一阶段的反向制动逻辑。

---

# 6. 第四阶段：快速反转，先做容易验证的部分

## Step 10：闭环主动制动 REV_BRAKE

**难度：中高**

先只做到“高速闭环减速到低速阈值”，不穿零。

**路径：**

~~~text
CLOSED_LOOP
-> 收到反向速度命令
-> 退出普通速度斜坡
-> 暂停速度 PI
-> 直接按斜率建立反向 Iq
-> observer 仍可信时继续闭环制动
-> 到低速阈值后暂时退出 / 保持
~~~

**重要：**

正转时负 Iq 是制动；真实速度穿零后相同负 Iq 会成为反向驱动。因此后续连续反转不需要交换相序，也不需要在零点再次翻转 Iq。

**第一轮暂不穿零。**

**验收：**

- +1500 rpm 可重复、平稳地制动到设定低速。
- -1500 rpm 对称验证。
- Iq 变化率受控。
- observer 可信区内角度稳定。
- 记录 Vbus 上升曲线。

---

## Step 11：先建立母线回馈限制，再允许更强制动

**难度：中高 / 安全关键**

制动电流不能只看相电流能力，还必须看母线吸收能力。

**本步骤目标：**

- 明确 Vbus 当前采样更新率。
- 测出制动时母线电压上升特性。
- 建立基于 Vbus 的制动力矩削减。
- 必要时增加软件过压预限制。
- 明确硬件最终过压保护边界。

概念上：

`Iq_brake_cmd = limit(request, current_limit, vbus_regen_limit)`

**禁止：**

在 Vbus 能量约束没有验证前，不提高快速制动电流去追求更短反转时间。

**验收：**

- 不同转速和负载下 Vbus 不超过定义的调试安全范围。
- Vbus 上升时 Iq 制动命令会按预期降低。
- 软件限制失效时仍保留硬件安全保护。

---

# 7. 第五阶段：最难部分——预测角穿零

## Step 12：建立预测器，但先只旁路观察

**难度：高**

先不让预测角控制电机。

observer 仍可信时记录：

- 最后可信角度。
- 最后可信速度。
- 当前 Iq。
- 实测减速度 / 加速度趋势。

后台计算预测：

`omega_pred(t)`

`theta_pred(t)`

并与 observer 仍可信区间的数据对比。

第一版先采用简单模型，不上复杂机械观测器。

**验收：**

- 在 observer 仍可靠的速度区间，预测角误差随时间的增长规律可测。
- 获得适合本电机 + 桨叶 + 水中负载的初始惯量 / 分段减速度参数。

---

## Step 13：REV_PREDICT 真正接管低速角度

**难度：高**

只有 Step 12 的预测误差明确以后才实施。

**路径：**

~~~text
REV_BRAKE
-> observer 可信度下降
-> 保存最后可信状态
-> theta_control 切到连续的预测角
-> 保持反向 Iq
-> 短时穿过零速盲区
~~~

**必须有退出条件：**

- 最大预测时间。
- 最大角度误差预算。
- 电流跟踪失败。
- 电压饱和。
- Vbus 异常。
- 其它故障。

第一轮可用约 30° 电角度的不确定度作为保守调试边界，后续由实测修改。

**重要：**

`omega_pred < 0` 只能表示模型预测已经穿零，不能当作“真实转子已经反转”的证明。

---

## Step 14：反向 Observer 恢复与 REV_HANDOVER

**难度：高**

反向运动重新具备可观测性后：

- observer 方向正确。
- BEMF / 磁链幅值重新达到有效范围。
- observer 角与预测控制角关系合理。
- 电流跟踪正常。
- 条件持续满足。

然后使用与静止启动类似的角度偏置渐消方法，完成预测角 -> observer 的无扰接管。

**验收：**

最终实现：

~~~text
+1500 -> 主动制动 -> 预测穿零 -> 反向 observer 恢复 -> -1500
-1500 -> 主动制动 -> 预测穿零 -> 正向 observer 恢复 -> +1500
~~~

两个方向分别验证，不能只验一个方向。

---

# 8. 第六阶段：电压模型优化

## Step 15：验证并引入互补电压重构

**难度：高**

等启动和换向主状态机已经可以独立工作后，再优化 observer 的电压输入：

`u_obs = u_measured + u_pwm_comp - H(u_pwm_comp)`

α、β 两轴分别执行。

其中：

- `u_measured`：三相 ADC 实测电压。
- `u_pwm_comp`：基于实际生效占空比，并考虑死区 / 管压降的 PWM 重构电压。
- `H()`：模拟实际板上 RC 的数字低通。

**目的：**

- 实测电压负责低频和实际压降偏差。
- PWM 重构负责快速变化。
- 两条路径处于一致的时间基准。

**必须先验证：**

- U/V/W 比例。
- U/V/W 偏置。
- 相序。
- RC 时间常数。
- 实际处理延迟。
- PWM 生效占空比。
- 滤波器初值。

**注意：**

20 ms 权重渐变只能减小切换突变，不能替代动态时间对齐。

# 9. 最终状态建议

最终状态枚举可以向以下结构发展，但不要第一步就全部加入：

~~~text
MOTOR_IDLE
MOTOR_ALIGN
MOTOR_OPEN_LOOP_IF
MOTOR_OBS_HANDOVER
MOTOR_CLOSED_LOOP
MOTOR_FLYING_CATCH
MOTOR_REV_BRAKE
MOTOR_REV_PREDICT
~~~
