# 系统架构总览（第一层：大结构）

> 本层先回答固件怎样运行、主循环和中断各做什么、数据怎样跨执行域传递。控制算法、采样时序和通信帧格式分别放在第二层；函数签名和字段含义放在第三层。

## 1. 一句话理解

上电后，主循环处理命令、CAN 和慢速电压采样；TIM1 定时触发 ADC 注入组，ADC1 JEOS 中断按 25 kHz 完成电流控制并更新 PWM。主循环发出运行目标，中断读取并执行；中断产生的运行数据供主循环读取和回传。

## 2. 主循环与中断：执行域总图

主循环放在中间，通信收发和 ADC JEOS 控制中断分列两侧。框内标出关键函数、接收队列和发送数据；跨域箭头表示数据交接。

~~~mermaid
flowchart LR
    CommIO[CAN 接收：FDCAN FIFO0<br/>MotorProtocol_PollRx → 协议帧环形队列<br/>CAN 输出：反馈帧 / 心跳帧<br/><br/>UART 接收：DMA 事件中断<br/>HAL_UARTEx_RxEventCallback → DebugConsole_OnRxEvent<br/>输出：字节环形队列<br/>UART 输出：文本 / 状态]

    MainLoop[主循环 · main.c<br/><br/>MotorProtocol_Process<br/>↓<br/>MotorApp_Process<br/>↻ 下一轮<br/><br/>输入：CAN 帧队列 / UART 字节队列 / FOC 反馈<br/>输出：run / 速度与电流目标<br/>电压快照 / CAN 与 UART 反馈]

    ControlIRQ[ADC JEOS 控制中断<br/><br/>输入：ADC 注入结果 / 共享目标与快照<br/>ADC1_2_IRQHandler<br/>HAL_ADCEx_InjectedConvCpltCallback<br/>MotorApp_OnInjectedConversion<br/>Observer_Run<br/>MotorApp_RunClosedLoop<br/>输出：TIM1 CCR1～3 / 电流 / 转速 / 状态]

    CommIO -->|CAN 协议帧队列 / UART 字节队列| MainLoop

    ControlIRQ -->|电流 / 转速 / 状态反馈| MainLoop
~~~

## 3. 两个主要执行域

| 执行域 | 进入方式 | 主要入口 | 职责 |
|---|---|---|---|
| 主循环 | main() 中的 while (1) | 先调用 MotorProtocol_Process()，再调用 MotorApp_Process() | 轮询 FDCAN FIFO0 并处理协议帧环形队列；按时隙发送 CAN 反馈和心跳；解析 UART 字节环形队列；软件触发规则组 ADC；根据运行请求和校准状态启动闭环 |
| ADC 控制中断 | TIM1 CH4 触发 ADC 注入组，ADC1 序列结束产生 JEOS | ADC1_2_IRQHandler() → HAL_ADCEx_InjectedConvCpltCallback() → MotorApp_OnInjectedConversion() | ADC 电流输入；零偏校准与闭环计算；更新 CCR1～3；发布电流、转速和运行状态 |

UART RX DMA 是事件驱动的短中断路径：HAL 回调把收到的字节交给控制台环形队列，完整命令由主循环解析。CAN 与 UART 一样经过队列缓冲，但入队方式不同：主循环中的 MotorProtocol_PollRx() 轮询 FDCAN FIFO0，把帧放入协议环形队列；MotorProtocol_Process() 再取帧解析，并调度反馈和心跳发送。CAN 接收不进入 ADC 控制中断。

## 4. 主循环与中断之间的数据交接

| 方向 | 数据 | 传递方式 | 用途 |
|---|---|---|---|
| CAN 总线 → 主循环 | 控制帧 | FDCAN FIFO0；MotorProtocol_PollRx() 轮询并写入协议帧环形队列 | MotorProtocol_Process() 取帧并解析启停、速度和电流目标 |
| 主循环 → CAN 总线 | 反馈帧、心跳帧 | MotorProtocol_Process() 调度，通过 FDCAN 发送 | 向上位机回传状态与运行数据 |
| UART DMA 回调 → 主循环 | 接收字节 | DebugConsole_OnRxEvent() 写入字节环形队列 | MotorApp_Process() 解析控制台命令 |
| 主循环 → ADC 中断 | 运行请求、速度和电流目标、速度环使能、波形开关 | 单个共享控制字段声明为 volatile；这不保证多字段成组一致 | 中断按当前请求决定运行状态和控制目标 |
| 主循环 → ADC 中断 | 母线及 U/V/W 端电压 | BoardAdc_Update() 写入快照；seqlock 序号保护整组读取 | 控制中断只接受前后一致的测量组 |
| ADC 中断 → 主循环 | 电流、转速、观测器、PWM 和运行状态 | 更新 FOC/应用状态，主循环或 CAN 反馈读取 | 串口诊断与周期反馈 |

普通状态字段逐项读取时可能来自不同控制周期；需要同一采样批次的一组规则组电压时使用 seqlock 快照。seqlock 的细节见[采样与板级](03-采样与板级.md#seqlock-并发机制)。

## 5. 启动链

启动初始化只执行一次，初始化完成后进入主循环；TIM1 CH4 与 ADC 注入组随后持续提供控制节拍。

~~~mermaid
flowchart LR
    Reset[复位入口]
    Safe[先将六路栅极驱动设为安全低电平]
    Clock[HAL 与 170 MHz 系统时钟]
    Board[FOC_Data_Init：板级和电机参数]
    Peripherals[初始化 GPIO、DMA、TIM1、ADC、OPAMP、CORDIC、FDCAN、USART]
    AppInit[MotorApp_Init：校准模拟前端并启动 ADC 注入和 TIM1 CH4]
    ProtocolInit[MotorProtocol_Init：启动 CAN 接收与协议状态]
    Main["进入主循环"]
    Reset --> Safe --> Clock --> Board --> Peripherals --> AppInit --> ProtocolInit --> Main
~~~

初始化顺序需要保持：FOC_Data_Init() → MX_TIM1_Init() → MotorApp_Init()。TIM1 初始化读取 foc.timer 中的 ARR、ADC 触发位置和死区参数。启动后功率桥保持关闭，前 1000 次 ADC 注入中断完成电流零偏校准；有效 run 请求到达后才进入闭环。

## 6. 控制中断内部路径

此图只展开 ADC 控制中断内的主路径。详细的计算公式和中间量见[控制层](02-控制层.md#控制中断完整流程)，ADC 的具体时序见[采样与板级](03-采样与板级.md)。

~~~mermaid
flowchart LR
    Sample[ADC 注入结果]
    Entry[检查 ADC1 和运行状态]
    Cal{零偏校准完成?}
    Accumulate[累加零偏并结束本次中断]
    Idle{当前为闭环?}
    Reset[保持 IDLE、关桥和清理闭环历史]
    Current[三相电流换算与 Clarke]
    Observer[电压融合与磁链观测器]
    Control[Park、PI、逆变换和 SVPWM]
    Write[写 CCR1～3]
    Sample --> Entry --> Cal
    Cal -->|否| Accumulate
    Cal -->|是| Idle
    Idle -->|否| Reset
    Idle -->|是| Current --> Observer --> Control --> Write
~~~

主循环接受启动请求后使能功率 PWM；停止请求由下一次 ADC 控制中断执行安全关断。IDLE 和 CLOSED_LOOP 是应用层运行状态；零偏校准在启动阶段的 IDLE 中完成。
