# 系统架构总览

> 阅读定位：先弄清“谁在何时读写什么”，再进入算法和寄存器。本文按本次工作区实际执行语句整理；源码存在、构建成功、实机通过是三种不同证据。

## 1. 工程边界与阅读地图

这个工程是 STM32G431 的无感 PMSM 驱动固件。它把三相电流变换到旋转坐标系，用电流 PI 决定电压，再把电压变成 PWM。转子角度不是由编码器读入，而是由电压、电流和电机模型估算。速度模式在电流环之外再加一层速度 PI；直接电流模式只跳过速度 PI，并不会跳过电流控制。

| 你要解决的问题 | 优先读哪篇 | 应找到的具体对象 |
|---|---|---|
| 上电之后程序如何开始跑 | 本篇、第 03 篇 | main、JEOS、运行门控、ADC 自检 |
| 一个控制拍到底算了什么 | 第 02 篇 | Clarke/Park、观测器、电流 PI、SVPWM |
| 为什么速度、电流数值不对 | 第 03 篇 | Rank、零偏、增益、采样有效窗口 |
| 命令如何进来，日志怎么解释 | 第 04 篇 | run 三个变量、CAN、status、startdiag |
| 某函数能否在中断里调用 | 第 05 篇 | 执行域、输入输出、共享状态、副作用 |

## 2. 五层结构：谁决定状态，谁计算输出

| 层 | 文件 | 责任 | 不应承担的责任 |
|---|---|---|---|
| 入口和事件转发 | main.c、stm32g4xx_it.c | 初始化顺序、主循环、HAL 回调转发 | 把电流环复制到多个 IRQ |
| 应用编排 | motor_app.c | 启停门控、启动/换向状态、参考仲裁、输出守卫 | 另维护一套与控制器冲突的电流 PI |
| 算法与状态估计 | controller.c、observer.c、foc_math.c/.h | PI、磁链/PLL、坐标变换、调制 | 自行接受 run 命令或决定整机重启 |
| 板级采集与执行 | adc.c、tim.c、opamp.c、board_adc.c 等 | 模拟通道、时序、引脚、慢速采样 | 把轮询式阻塞操作放入 25 kHz 中断 |
| 通信、构建与资料 | debug_console.c、motor_protocol.c、CMake、doc | 命令解析、反馈、布局和使用说明 | 把通信成功当作电机同步证明 |

`Drivers/` 与 `Middlewares/` 是依赖库。`AS5600.c` 是保留接口，未列入当前固件源清单；不能把它当作当前独立测速通道。旧 `app_boot_control.c` 虽被构建清单包含，主路径的 Boot 管理实际走 `motor_protocol.c`。依据：[`CMakeLists.txt`](../CMakeLists.txt#L1)、[`MotorProtocol_HandleBoot()`](../Core/Src/motor_protocol.c#L323)。

## 3. 三个执行域，而不是三个独立控制器

```text
主循环                     ADC1 JEOS                    TIM6 1 ms
MotorProtocol_Process      OnInjectedConversion         MotorProtocol_TimerTick
  CAN队列消费                电流/端电压采样                CAN时隙反馈
MotorApp_Process             观测与状态推进                不执行速度PI
  串口组行/解析              唯一参考仲裁
  母线与温度轮询             唯一电流控制链
  启动门控                   PWM写入与状态交接
```

速度 PI 的 1 kHz 来自电流控制拍中的 **25 分频**，不是 TIM6 另开一个速度环。串口接收与 CAN 接收中断先搬运数据，语义解析留给主循环。这样外部命令的到达时刻与控制器正式采用命令的时刻被分开。

来源：[`MotorApp_Process()`](../Core/Src/motor_app.c#L1826)、[`DebugConsole_Process()`](../Core/Src/debug_console.c#L323)、[`MotorProtocol_Process()`](../Core/Src/motor_protocol.c#L605)、[`MotorProtocol_TimerTick()`](../Core/Src/motor_protocol.c#L573)。

## 4. 上电到“可以启动”的完整因果链

1. `main()` 设置 `SCB->VTOR = APP_FLASH_START`，随后先把六路桥控制引脚置低，再做 HAL、时钟和外设初始化。
2. `FOC_Data_Init()` 写入 PWM 周期、采样增益、电机模型和观测器配置；它必须早于 `MX_TIM1_Init()`，后者会读取这些参数。
3. `MotorApp_Init()` 初始化 DWT、CORDIC、控制器、控制台、运放与 ADC，规则组取得母线初值；启动 ADC2 注入转换和 ADC1 注入中断。
4. 将 ADC1 完成事件配置为 **整段注入序列结束 JEOS**，回读 JSQR 检查通道顺序，最后启动 CH4 采样触发。相输出尚未执行正常驱动。
5. IDLE 下采集三相各 1000 拍零点，约 40 ms。`cal=1` 后仍不自动运行；等待外部 run 请求。

来源：[`main()`](../Core/Src/main.c#L76)、[`FOC_Data_Init()`](../Core/Src/foc_math.c#L33)、[`MotorApp_Init()`](../Core/Src/motor_app.c#L1694)、[`MotorApp_ForcePowerStageSafe()`](../Core/Src/motor_app.c#L1646)。

配置自检只核对寄存器布局；它不证明电流极性、外部增益、相序和电压分压全部正确。READY 文本也只表示接口已准备，不能代替机械静止确认。

## 5. 一次 run 命令实际经过哪些门

```text
set run 1 / CAN启动帧
  → 写 motor_run_command（用户意图）
  → MotorApp_ApplyRunCommand()
  → motor_run_requested（中断运行许可）
  → MotorApp_Process() 启动前置门控
  → MotorApp_StartControlSequence()
  → ALIGN，FOC_PWM_Start()
```

| 变量 | 谁改变它 | 语义与重要反例 |
|---|---|---|
| motor_run_command | 控制台或协议请求 | `OK run=on` 只确认命令写入 |
| motor_run_requested | 应用门控和故障路径 | 用户仍请求运行时，也可以被故障强制清零 |
| motor_fault_latched | 故障入口；显式 run 0 解除 | 重复 run 1 不能穿过故障闭锁 |
| motor_idle_reset_done | 中断首次 IDLE 复位 | 避免主循环在控制器尚未复位完整时开新启动 |
| motor_adc_cfg_ok | 初始化自检 | 默认必须通过；不建议为启动而关闭检查 |
| foc.calibration.calibrated | 中断零偏累加 | 完成校准是开桥前置条件，不是观测器就绪 |

`MotorApp_Process()` 将运行许可、未闭锁、ADC 配置许可、校准完成、IDLE 复位完成、当前 IDLE 六项组合判断。实际开桥前又进入短临界区复查，避免在检查与提交之间被停止请求打断。来源：[`MotorApp_ApplyRunCommand()`](../Core/Src/motor_app.c#L606)、[`MotorApp_Process()`](../Core/Src/motor_app.c#L1826)、[`MotorApp_StartControlSequence()`](../Core/Src/motor_app.c#L1265)。

## 6. 一拍内的数据年龄与计算顺序

| 本拍位置 | 使用/产生的数据 | 需要注意的“一拍差” |
|---|---|---|
| 读取注入组 | 本批 Ia/Ib/Ic、U/V/W | 不同 Rank 是顺序转换，不是同一瞬间 |
| Clarke 与观测输入 | 本批电流/端电压，缓存的占空比 | 重构电压采用上次已计算的 PWM 占空比；不能用尚未输出的新命令 |
| Advance / Observer / Ready | 更新磁链和速度，推进虚拟轨迹 | Ready 此时看到的 dq 电流与 PI 饱和状态仍来自上次 Park/PI |
| Resolve | 本拍角度、Id/Iq、速度模式与斜坡覆盖 | 启动与闭环都只从这一条参考入口进入控制器 |
| RunCurrentLoop | 本拍 Park、电流 PI、调制结果 | 速度 PI 只在分频到点时更新目标，Iq 限速仍逐拍推进 |
| 守卫与 CCR 写入 | 最终有限性检查、主动状态再确认 | 故障已经关桥就不能在同一回调后段重新写回驱动 |
| 拍末 Transition / 波形 | 常规状态交接、可选诊断发送 | 波形中的阶段可能已变成下一状态，电流却是刚完成的上一阶段 |

通常的 ALIGN→I/f→HANDOVER→CLOSED 由拍末函数提交。**例外是运行中进入低速 I/f**：`MotorApp_BeginForcedOpenLoop()` 可在 `Advance` 内直接改状态，以便本拍先承接旧角度与电流。不能把“所有切换都在拍末”作为全局假设。来源：[`MotorApp_OnInjectedConversion()`](../Core/Src/motor_app.c#L1877)、[`MotorApp_AdvanceStateMachine()`](../Core/Src/motor_app.c#L1036)、[`MotorApp_UpdateStateTransition()`](../Core/Src/motor_app.c#L1186)。

## 7. 当前状态机与控制来源

| state | 名称 | 控制角来源 | 速度环 | 退出/保持规则 |
|---:|---|---|---|---|
| 0 | IDLE | 不执行主动 Park 控制 | 不运行 | 关桥、保留采样，等待合法启动 |
| 2 | ALIGN | 固定 0 rad | 关闭 | Id=1 A 定位 30 ms |
| 3 | OPEN_LOOP_IF | 虚拟积分角 | 关闭 | 低速目标长期强拖；高速目标到接管点后验证 |
| 4 | OBSERVER_HANDOVER | phase_raw + 渐消偏置 | 关闭 | 20～150 ms 坐标交接，电流模式与速度模式 q 策略不同 |
| 1 | CLOSED_LOOP | 估计磁链角 phase_raw | 依配置；制动可强制投入 | 50 ms 参考保持后正常运行；低速/反转进入衔接路径 |

`phase` 不是第六种状态，而是诊断子阶段编号：10=闭环初始保持，12=高速闭环制动；30/31=I/f 加速/验证，32=低速强拖，33=穿零前制动。编号 11 当前不存在。来源：[`MotorApp_StartupPhaseCode()`](../Core/Src/motor_app.c#L1374)。

## 8. 共享对象的所有权与快照边界

| 对象 | 主要写者 | 读者 | 一致性方式 |
|---|---|---|---|
| 命令与可调增益 | 主循环命令解析 | ADC 控制路径 | volatile 读写；多个字段不是事务 |
| startup / 控制器运行态 | ADC 控制路径，启动时短临界区重建 | 诊断和波形 | 普通 status 多行不保证同一拍 |
| board_adc_measurements | 主循环 BoardAdc_Update | 同主循环读取 | 局部 next 成功后赋值；没有 seqlock |
| foc.state.vbus / temperature | 主循环从规则组复制 | 中断、通信 | 两个字段不等于一次原子成组发布 |
| HANDOVER / CLOSED / FAULT / LOW_ENTER | 中断捕获 | 主循环打印 | valid 发布标志；打印前短临界区整体复制 |
| CAN 接收环形队列 | CAN IRQ 生产 | 主循环消费 | head/tail + 内存屏障；满时丢弃 |

`volatile` 不会自动提供多字段一致性，也不是互斥锁。`status` 是观察入口，不是全局冻结后的原子镜像。来源：[`MotorApp_CaptureDiagnostic()`](../Core/Src/motor_app.c#L546)、[`MotorApp_PrintDiagnostic()`](../Core/Src/motor_app.c#L1392)、[`BoardAdc_Update()`](../Core/Src/board_adc.c#L21)、[`HAL_FDCAN_RxFifo0Callback()`](../Core/Src/motor_protocol.c#L488)。

## 9. 正确理解保护、停止和时间预算

故障入口先清 MOE，锁存首个故障，清运行许可，再清 CCR 并返回 IDLE。普通 IDLE 会停止六路相输出、清 PI 与观测器，但保留 CH4 采样、零偏结果、命令和增益。`set speed 0` 是停止语义，不是“带电锁定 0 rpm”。

当前 `MOTOR_APP_CLOSED_LOOP_HEALTH_ENABLE=0`，持续跟踪健康跳闸未启用；TIM1 Break/Break2 也在配置中关闭。已有非有限数、母线非法、接管符号与输出守卫，不等于已经具备完整过流/过压/过温保护。板外保护能力仍要另核对。

25 kHz 名义周期是 40 μs，在 170 MHz 下为 6800 个 CPU 周期。DWT 输出当前可同时显示周期数、微秒和占用率，但只覆盖回调主体，未包含全部中断分发、等待与返回成本。不能凭“函数小于40 μs”就证明最坏工况无丢拍。来源：[`MotorApp_EnterFault()`](../Core/Src/motor_app.c#L586)、[`MotorApp_DebugStatus()`](../Core/Src/motor_app.c#L1441)、[`Core/Src/tim.c`](../Core/Src/tim.c#L1)。

## 10. 最容易读错的六个结论

- “开环”在这里主要指角度/速度来源，电流环仍然闭合。
- `phase_raw` 与 `pll_phase` 都是估计角，均不应称为真实角。
- 运行换向不再等于重新 ALIGN；低速边界要承接已有状态。
- 新命令回显不等于开桥成功，更不等于达到命令转速。
- 规则组母线值有限且大于零不证明足够新鲜；当前没有独立年龄检查。
- 当前磁盘未找到 `tests/`。网页保留的测试文本是历史快照，不能直接当作可执行回归入口。
