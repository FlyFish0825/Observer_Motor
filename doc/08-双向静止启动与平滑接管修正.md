# 双向静止启动、坐标接管与运行低速衔接

> 本文是本次源码的现行专题，不再把多版参数混排成“当前行为”。它描述软件如何选择控制角、电流和目标；不宣称真实电机已完成全部负载/反转验收。

## 1. 一张图分清冷启动与运行换向

```text
冷启动：
IDLE → ALIGN → I/f
  ├─ 低速命令(|n|≤800)：保持虚拟角控制
  └─ 高速命令：拖到min(|n|,1000) → Ready → HANDOVER → CLOSED

运行降速/换向：
CLOSED（仍用观测角制动）
  → 原始与控制速度都进入±800
  → 承接角度/电流/有效减速率，进入运行I/f
  → 低速目标保持 或 有符号轨迹穿零、向反方向加速
  → 高速目标重新Ready → HANDOVER → CLOSED
```

两条路径共用电流控制器，但初始化不同。运行换向不重新ALIGN，不把虚拟速度归零，不清已有电流PI。来源：[`MotorApp_StartControlSequence()`](../Core/Src/motor_app.c#L1265)、[`MotorApp_BeginForcedOpenLoop()`](../Core/Src/motor_app.c#L486)、[`MotorApp_AdvanceStateMachine()`](../Core/Src/motor_app.c#L1036)。

## 2. 状态、phase与采用的信号

| 状态/phase | 控制角 | 电流参考 | 速度反馈/速度PI |
|---|---|---|---|
| IDLE=0 | 不执行主动控制 | 输出关闭 | 控制器复位 |
| ALIGN=2 | 0 rad | Id=1A、Iq=0 | 不跑速度PI |
| IF=3，phase30/31 | if_angle | 冷启动有方向1.5A | 虚拟速度；速度PI关 |
| IF=3，phase32/33 | 连续if_angle | 运行承接Iq，方向依轨迹变化 | 虚拟速度；速度PI关 |
| HANDOVER=4 | phase_raw+offset | 观测系d退零；q依模式处理 | 100Hz控制反馈；速度PI仍关 |
| CLOSED=1，phase10 | phase_raw | Id淡入、Iq受20A/s约束 | 50ms内参考保持，PI工作 |
| CLOSED=1，phase1/12 | phase_raw | 速度PI或直接Iq；100A/s | 正常调速或观测闭环制动 |

Ready使用pll_phase而不是最终控制用phase_raw。故障快照的delta是控制角减phase_raw；这两个角差不是同一个量。

## 3. 静止启动入口：允许启动不等于已经同步

启动函数校验命令、Ts、极对数和母线；主循环前置门还检查run、自检、校准、IDLE复位与故障锁存。短临界区内停触发、重建startup、清本次快照、锁方向并设ALIGN，然后开启PWM。

定位30ms只说明给定固定坐标电流一段时间，不证明每个初始位置都完全收敛。未知转子角下“定位Iq=0”不等于完全没有机械转矩；该电流本来就可能使转子移动去对齐。

低目标不再按历史550rpm入口门槛拒绝。非零且|命令|≤800会选择长期I/f；用户speed=0在主动流程中被解释为停止，不是保持带电零速。

来源：[`MotorApp_Process()`](../Core/Src/motor_app.c#L1826)、[`MotorApp_StartControlSequence()`](../Core/Src/motor_app.c#L1265)、[`MotorApp_ResolveControlReference()`](../Core/Src/motor_app.c#L638)。

## 4. I/f轨迹：速度是给定，不是实测

冷启动电角加速度600rad/s²，p=7时约818.5机械rpm/s，Iq幅值1.5A。高速目标先限到1000rpm供接管，之后闭环追随最终命令。虚拟轨迹走到1000不能证明转子也到了1000。

当前统一使用有符号速度斜坡与梯形角积分：

```text
ωnext = slew(ωprevious, ωtarget, αe·Ts)
θnext = wrap(θprevious + 0.5·(ωprevious+ωnext)·Ts)
```

绝对速度幅值与方向分开存储，轨迹通过零点时角度连续。运行I/f的Iq符号来自target−previous：正转由790降到500也可能需要负Iq，不能只按目标仍为正就给正转矩。

来源：[`MotorApp_Slew()`](../Core/Src/motor_app.c#L445)、[`MotorApp_AdvanceStateMachine()`](../Core/Src/motor_app.c#L1036)。

## 5. Ready：信号选择、去抖和等待上限

| 项目 | 当前值/对象 | 含义 |
|---|---|---|
| 角连续性/净覆盖/漂移 | pll_phase | 不是phase_raw直接差分 |
| 速度匹配 | speed_rpm_f−virtual_rpm | 两级30Hz滤波；±40rpm |
| 原始快速门 | speed_rpm | 绝对值≥800、方向正确、单拍≤100rpm |
| 单拍角变化 | ≤0.35rad，反向容差−0.01rad | 角差做wrap，正常跨±π不能误认为2π跳变 |
| 绝对角差门 | 开关0 | 85°阈值保留但当前不生效 |
| 相对锚点漂移 | ≤1.0rad | 窗口起点重新建立锚点 |
| 电流跟踪 | \|Id\|≤0.8A、\|Iq−Iq_ref\|≤0.5A、无PI饱和 | 连续坏2ms才置TRACK |
| 连续资格 | 750拍且净角≥2π | 任一失败会清连续计数和跨度 |
| 验证总等待 | 1500ms / 37500拍 | 与连续合格计数不是同一个计时器 |

电流反馈检查发生在本拍Park之前，读取的是上拍dq与饱和标志。历史位只在验证窗口内积累，不把加速时必然出现的RAMP混为验证失败。

**4s并非全程墙钟超时。** 当前total_count只在非forced的ALIGN、HANDOVER以及已开启verify的IF阶段递增，普通IF爬坡不在这一累计条件里；低速forced段也不按它超时。因此文档不能承诺“发run后必定4s内结束一切启动”。

来源：[`MotorApp_UpdateObserverReady()`](../Core/Src/motor_app.c#L800)、[`MotorApp_UpdateStateTransition()`](../Core/Src/motor_app.c#L1186)、[`MotorApp_AdvanceStateMachine()`](../Core/Src/motor_app.c#L1036)。

## 6. 为什么末拍mask为0仍会fail=1

假设每20ms出现一个不合格拍，其余全部合格，最长连续段只有499拍，达不到750；1.5s结束时最后一拍完全可能正常。这只是解释计数机制的合成输入，不是对某次电机真实失败的回放。

当前status有rdy_fail、rdy_hist、rdy_count、rdy_max与span；快照mask则合并当前位与历史位。rdy_hist有0x100只说明窗口内出现过速度匹配失败，不能推断它每一拍都错或出现次数最多。下一步需要频次/时间序列时应专门增加统计，不凭末拍数据补推整段波形。

## 7. 坐标接管的数学与当前q策略

交接起点令δ0=wrap(θ_control−phase_raw)，将最后施加的参考旋到观测系：

```text
d0 = id_control·cosδ0 − iq_control·sinδ0
q0 = id_control·sinδ0 + iq_control·cosδ0
```

非有限或q0×当前运动方向≤0会fail7；绝对角差检查关闭不取消这个门。当前不是采一个噪声电流值就替换所有参考，而是从已经采用的参考向量开始转换。

令x为0～1交接进度，b=1−x²(3−2x)：

```text
offset = δ0·b
dobs* = d0·b
qobs* = q0·b²   （用户请求速度模式）
qobs* = q0      （直接电流模式）
θcontrol = phase_raw + offset

id* = dobs*·cos(offset) + qobs*·sin(offset)
iq* = −dobs*·sin(offset) + qobs*·cos(offset)
```

同时按旧offset−新offset搬运Id/Iq PI积分。交接时间由偏置大小和速率参数推算后限制在20～150ms。钳住最大时间也意味着大偏置时不能把20rad/s当作无条件严格偏置速率上限，应按实际总时间检查。

速度模式q退零是当前策略，不能再写“整个接管转矩恒定”；它减少继续加速的驱动请求，也可能使重载转速下降。参考连续并不保证机械速度不变。

来源：[`MotorApp_BeginObserverHandover()`](../Core/Src/motor_app.c#L949)、[`MotorApp_ResolveControlReference()`](../Core/Src/motor_app.c#L638)、[`FOC_Control_RotateCurrentIntegrals()`](../Core/Src/controller.c#L1241)。

## 8. 从接管结束到正常速度闭环

拍末转CLOSED后，下一控制拍检测速度模式边沿，参考从当前100Hz控制反馈播种、速度积分接住当时有效Iq。50ms内冻结**参考的推进**，不是关闭速度PI；Id命令按比例淡入，Iq采用20A/s约束。

50ms到期直接放开运行配置，不再等待参考与反馈对最终目标“连续稳定”。正常参考默认20000rpm/s，Iq采用100A/s；减速满足控制器条件时参考可采用60000rpm/s。三者都是软件参考约束，不是机械响应保证。

电流模式speed_en=0不会运行速度PI，但处于CLOSED状态时仍使用观测角、电流PI与PWM。对用户来说“state1”不总等于“速度双闭环已开启”，还应看本拍采用的speed_en。

来源：[`FOC_Control_Run()`](../Core/Src/controller.c#L891)、[`MotorApp_UpdateStateTransition()`](../Core/Src/motor_app.c#L1186)。

## 9. 运行制动：先把真实运动带回可信边界

收到反向目标时内部闭环速度目标先设0，而不是把远端−8000直接作为当前制动段的虚拟率。目标是同向低速则采用低目标。原始PLL速度与100Hz控制反馈**都**进入±800后才调用低速入口；不以内部参考先过零作为机械进入低速的替代。

当前低速边界判断仍依赖观测值，不应称为直接测得真实速度。高速制动也不能代替母线回馈能量约束；电源不能吸收能量时仅有Iq限幅仍不够。

来源：[`MotorApp_AdvanceStateMachine()`](../Core/Src/motor_app.c#L1036)、[`MotorApp_ResolveControlReference()`](../Core/Src/motor_app.c#L638)。

## 10. 低速入口：承接角度、电流、速度和估计斜率

`MotorApp_BeginForcedOpenLoop()`的关键动作：继承phase_raw（接管中加上剩余偏置）、当前控制反馈速度、Id/Iq参考；保留已有电流PI；记录LOW_ENTER，segment递增，再进入IF。

减速度只在CLOSED且两种速度绝对值>800时估计，每5ms差分，10ms一阶滤波，至少3次有效样本并满足方向/电流条件。有效时冻结这段观测派生率进入I/f；缺失时回退到冷启动600电角rad/s²，并受配置speed_slew限制。

继承的有效实测率当前不再被默认speed_slew二次削弱；因此“把speed_slew设小就必然减小所有低速衔接加速度”不成立。measured标志能帮助区分哪条分支。

如果旧闭环正在输出更大的制动电流，入口保留其幅值而不突降1.5A；到低速目标后再受限回落到默认强拖电流。换向过零时不会对Iq做第二次机械符号翻转。

来源：[`MotorApp_UpdateMeasuredAcceleration()`](../Core/Src/motor_app.c#L454)、[`MotorApp_BeginForcedOpenLoop()`](../Core/Src/motor_app.c#L486)。

## 11. 辅助观测失效、重新接管与退出

I/f段观测器只辅助估计，失去有限性时允许按虚拟角/速度重新播种，清Ready资格，但不触碰实际控制角轨迹与电流PI。重新播种不等于建立了物理同步，也不允许直接置Ready。

进入HANDOVER或CLOSED后依赖观测，关键量非有限走故障退出。高目标从IF重新到位后必须通过完整Ready，不因“此前曾经闭环过”跳过资格。低目标长期forced运行不等待Ready。

当前持续跟踪健康开关0，不能把“运行期间不跳fail2”当作健康证明。母线/数值/接管参考符号守卫仍存在。来源：[`MotorApp_RecoverAuxObserver()`](../Core/Src/motor_app.c#L1003)、[`MotorApp_EnterFault()`](../Core/Src/motor_app.c#L586)。

## 12. 用三个场景检验理解

**正向静止1500rpm。** 定位、虚拟速度到1000、Ready、坐标接管、50ms参考保持、向1500推进。此顺序是控制设计，不保证独立机械转速精确跟随虚拟线。

**正向790rpm降到500rpm。** 当前可能已在低速I/f；虽然目标还是正值，减速阶段Iq可以为负。到位后强拖维持策略与减速转矩策略不同，须分别观察。

**正向2000rpm改成−8000rpm。** 高速闭环内部先向0减速，双反馈进入±800后承接LOW_ENTER，再连续虚拟轨迹过零、向−1000加速；重新Ready/接管后才向最终−8000推进。不能把−8000幅值直接当作盲区恒加速度的来源。

### A. 运行低速入口的状态承接

[`MotorApp_BeginForcedOpenLoop()`](../Core/Src/motor_app.c#L486)

以下为当前实现的阅读摘录，移除注释与空行；省略外围内容时不改变原控制分支的含义。

```c
static void MotorApp_BeginForcedOpenLoop(float command) {
  float speed = foc.observer.state.speed_rpm_f;
  float target = copysignf(fminf(fabsf(command), MOTOR_APP_HANDOFF_TARGET_RPM), command);
  float motion = target - speed;
  float requested_rate = motor_control.speed_slew_rpm_per_s;
  startup.if_angle = foc.observer.state.phase_raw;
  if (foc_motor_state == FOC_MOTOR_OBSERVER_HANDOVER)
    startup.if_angle = FOC_WrapToPiFast(startup.if_angle +
                                      startup.handover_last_offset);
  startup.if_direction = (speed < 0.0f) ? -1.0f : 1.0f;
  startup.if_speed_rad_s = MotorApp_RpmToElectricalRad(speed);
  startup.if_ramp_rpm_s = MOTOR_APP_IF_ACCEL_RAD_S2 * 60.0f /
      (CORDIC_TWO_PI_F * (float)foc.observer.motor.pole_pairs);
  startup.if_measured_ramp =
      (startup.accel_samples >= MOTOR_APP_ACCEL_VALID_SAMPLES) &&
      isfinite(startup.measured_accel_rpm_s) &&
      (fabsf(startup.measured_accel_rpm_s) > 1.0f) &&
      (startup.measured_accel_rpm_s * motion > 0.0f) &&
      (motor_control.iq_ref_active * motion > 0.0f);
  startup.if_iq_magnitude = MOTOR_APP_IF_IQ_A;
  if ((motor_control.iq_ref_active * motion > 0.0f) &&
      (fabsf(motor_control.iq_ref_active) > startup.if_iq_magnitude))
    startup.if_iq_magnitude = fabsf(motor_control.iq_ref_active);
  if (startup.if_measured_ramp != 0U) {
    startup.if_ramp_rpm_s = fabsf(startup.measured_accel_rpm_s);
  }
  if (!isfinite(requested_rate) || (requested_rate < 0.0f)) requested_rate = 0.0f;
  startup.if_accel_rad_s2 = MotorApp_RpmToElectricalRad(
      (startup.if_measured_ramp != 0U) ? startup.if_ramp_rpm_s :
      fminf(startup.if_ramp_rpm_s, requested_rate));
  startup.if_iq_reference = motor_control.iq_ref_active;
  startup.if_id_reference = motor_control.reference.id_ref;
  startup.runtime_if = 1U;
  startup.closed_loop_braking = 0U;
  startup.speed_startup_active = 0U;
  MotorApp_SetOpenLoopTarget(command);
  startup.segment++;
  motor_handover_snapshot.valid = 0U;
  motor_closed_snapshot.valid = 0U;
  MotorApp_CaptureDiagnostic(&motor_low_enter_snapshot, MOTOR_APP_FAIL_NONE);
  startup.accel_initialized = 0U;
  foc_motor_state = FOC_MOTOR_OPEN_LOOP_IF;
}
```


重点看四个承接量：if_angle、if_speed_rad_s、if_iq_reference、if_id_reference。它们与冷启动从定位角/零速建立轨迹完全不同。读取LOW_ENTER时若state仍为1或4，不是捕获失败，而是记录发生在最后改state之前。

### C. 时间尺度验算

按600电角rad/s²、7极对，冷启动虚拟轨迹从0到1000rpm名义约1.222s，再加30ms定位；Ready首次连续合格至少30ms。此后接管取决于初始偏置，20～150ms，闭环再有50ms参考保持。这个算例给程序轨迹量级，不是实际电机保证完成时间。

当|offset0|=70°，按公式1.5|offset|/20得到约91.6ms，处于时间限幅内。在这一段速度模式q按blend²下降，因此只看接管前后两点的Iq数值不足以描述中间转矩时程。

### D. 重复启动与中途改命令的边界

| 时刻 | 输入 | 当前主要处理 | 验证点 |
|---|---|---|---|
| 已闭锁 | 再发run1 | 保持不许可 | 不应自动清首故障 |
| 已闭锁 | run0 | 解除闭锁许可条件 | 先保存快照，新的run可能覆盖 |
| ALIGN/IF | 目标方向或接管目标变化 | 刷新本段目标与验证窗口 | 角/电流过渡与total_count重置口径 |
| HANDOVER/CLOSED | 反向或低目标 | 计算制动标志并检查低速入口 | 不把远端目标直接变盲区率 |
| 运行I/f | 同向减速但目标仍正 | 转矩方向看轨迹变化 | Iq可负，不能误判方向错 |
| 任意主动状态 | speed0 | 撤销输出并停止 | 不进入有力矩的0rpm保持 |

### E. 接管策略的可证伪假设

假设1：“持续资格被噪声打断”。证据应该是速度/角度时序和失败位清零事件，而不是只有终止拍。假设2：“接管q退零足以避免过冲”。证据要比较q投影、CLOSED快照、机械速度与负载；若速度仍跃升，也应查观测速度本身和参考轨迹。假设3：“继承可信减速度能覆盖盲区”。需要独立过零时刻和低速负载数据，若虚拟过零明显早于转子，就说明该假设在此工况不成立。

以上假设都不是为了证明既有方案正确而挑选数据，而是为了发现下一次需要修改的具体机制。
