# 上手实操手册（补充资料）

> 本文面向**第一次拿到这块板子和这份工程的人**，回答"从零到电机转起来要做什么"。
> 它只写操作步骤与现场判断，不展开原理（见[控制层](02-控制层.md)），不列全部参数（见[参数与调参速查](10-参数与调参速查.md)）。
> **首次上电必须空载 + 限流 + 手不离断电开关。**

---

## 0. 一分钟速览

~~~text
装工具链 → 选对预设构建 → 按布局烧录 → 接串口 → 上电看 READY
  → status 确认 cal=1 / adc_cfg=1 → set speed 1500 → set run 1 → 观察
~~~

---

## 1. 硬件与依赖清单

### 1.1 硬件

| 项 | 说明 |
|---|---|
| 目标板 | STM32G431CBT6 电机控制板 |
| 调试器 | ST-Link（SWD），`.vscode` 中配置的是 STLINK |
| 功率电源 | 可调直流电源，**首次务必限流** |
| 电机 | 本项目默认参数对应：`Rs = 0.5 Ω`、`Ls = 100 µH`、磁链 `2.84 mWb`、**7 极对** |
| 串口 | USART1（PB6/PB7），**2,000,000 baud** |
| 母线电压 | 软件限幅按 `voltage_limit = Vbus/√3` 计算，不要超过硬件耐压 |

> 24 MHz 的 CBU6 测试板串口是 USART2（PB3/PB4），与正式板不同。跨板测试只用于验证 CAN/Boot 通信，**不能据此确认电机采样与驱动功能**。

### 1.2 软件

| 项 | 说明 |
|---|---|
| CMake | ≥ 3.22（`CMakeLists.txt:1`） |
| Ninja | 四个预设都用 Ninja 生成器 |
| arm-none-eabi GCC | 工具链文件 `cmake/gcc-arm-none-eabi.cmake` |
| OpenOCD | 烧录与调试（`.vscode/tasks.json` 里用的是 EIDE 自带的路径） |
| Python 3 | 跑主机回归测试与 `codecheck.py` |
| 本机 gcc | 主机回归必需（脚本用 `shutil.which('gcc')`，找不到会直接退出） |
| 串口终端 | 例如 `python -m serial.tools.miniterm`（`.vscode/tasks.json` 已有现成任务） |

> `.vscode/launch.json` 与 `.vscode/tasks.json` 里的工具路径是**某台机器的绝对路径**（`C:/Users/Administered/.eide/tools/…`），换机器必须改。

## 2. 选对镜像：先想清楚烧到哪

这是最容易出错的一步。**同一套源码会生成多个布局不同的镜像，不要按同一地址烧录。**

| 预设 | APP 起始地址 | 由谁加载 | 输出 BIN | 什么时候用 |
|---|---|---|---|---|
| `Debug` | 0x08000000 | SWD 直接启动 | `build/Debug/Observer_standalone.bin` | CBT6 板独立调试 |
| `Release` | 0x08000000 | SWD 直接启动 | `build/Release/Observer_standalone.bin` | CBT6 板独立运行 |
| `Boot-Release` | 0x08005000 | 外部 Bootloader | `build/Boot-Release/Observer_boot.bin` | CBT6 板 Bootloader 升级 |
| `Boot-Release-HSE24` | 0x08005000 | 外部 Bootloader | `build/Boot-Release-HSE24/Observer_boot_hse24.bin` | CBU6 板（24 MHz）CAN/Boot 临时验证 |

判断依据只有两条：**板子上有没有 Bootloader**，以及**晶振是 16 MHz 还是 24 MHz**。

- 有 Bootloader → 用 `boot` 布局，烧到 `0x08005000`；`APP_FLASH_START` 同时控制链接地址与 `SCB->VTOR`。
- 没有 Bootloader → 用 `standalone` 布局，烧到 `0x08000000`。
- 晶振不确定 → 打开 `Core/Inc/board_clock.h`，看 `BOARD_HSE_HZ`（默认 `16000000UL`）。选错晶振**串口波特率会是错的**，表现为乱码或完全无输出。

## 3. 构建

### 3.1 命令行（推荐）

工作目录是工程根目录：

~~~powershell
cd <工程根目录>

# 独立调试版
cmake --preset Debug
cmake --build --preset Debug

# 独立优化版
cmake --preset Release
cmake --build --preset Release

# Boot 版（16 MHz）
cmake --preset Boot-Release
cmake --build --preset Boot-Release

# Boot 版（24 MHz CBU6 测试板）
cmake --preset Boot-Release-HSE24
cmake --build --preset Boot-Release-HSE24
~~~

产物：

| 文件 | 说明 |
|---|---|
| `build/<预设>/Observer.elf` | 可调试、可给 OpenOCD 烧录 |
| `build/<预设>/Observer_standalone.bin` | standalone 布局的纯二进制 |
| `build/<预设>/Observer_boot.bin` | boot 布局的纯二进制 |
| `build/<预设>/Observer_boot_hse24.bin` | 24 MHz 变体 |
| `build/<预设>/compile_commands.json` | clangd 索引（`CMAKE_EXPORT_COMPILE_COMMANDS` 已开） |

> Release 下应用源码用 `-O3 -flto`，**覆盖工具链默认的 `-Os`**（因为 `-O3` 出现在命令行更后面）。LTO 允许 GCC 跨 `main.c`/`foc_math.c`/`observer.c`/`controller.c` 内联。

### 3.2 VS Code 任务

`.vscode/tasks.json` 提供：

| 任务 | 作用 |
|---|---|
| `Build STM32 Release` / `Build STM32 Debug` | 构建对应目录 |
| `OpenOCD Flash STM32 Release` / `… Debug` | 先构建再用 OpenOCD 烧 `Observer.elf`，随后 `verify reset exit` |
| `Open COM27 motor_identify` | 打开串口终端：`COM27`，**2000000** 波特率，行结束符 `LF` |

> `COM27` 是硬编码的端口号，换机器要改。烧录任务只覆盖 `Release` 与 `Debug` 两个 standalone 布局；**Boot 布局没有现成任务**，需要手动用 OpenOCD 烧。

### 3.3 手动烧录（脱离 VS Code）

~~~powershell
openocd -f interface/stlink.cfg -f target/stm32g4x.cfg `
        -c "program build/Release/Observer.elf verify reset exit"
~~~

Boot 布局把路径换成 `build/Boot-Release/Observer.elf`。**烧录地址由 ELF 自身的链接地址决定**，用 ELF 烧录比用裸 BIN 安全。

### 3.4 构建后的自检

~~~powershell
Get-Item build\Release\Observer.elf | Select-Object LastWriteTime, Length
Get-FileHash build\Release\Observer_standalone.bin -Algorithm SHA256
~~~

时间戳没变说明没有真正重新编译。参考的 Flash 占用见[测试与验证指南](12-测试与验证指南.md#43-期望的-flash-占用)。

## 4. 接线与安全检查

### 4.1 上电前检查清单

- [ ] 母线电源处于**关闭**状态，或已设好限流。
- [ ] 三相线、母线、地线接牢，无裸露短路风险。
- [ ] ST-Link 已连接（若需要现场调试）。
- [ ] 串口线已连接 PB6/PB7（GND 共地）。
- [ ] 电机**空载**（首次验证）。
- [ ] 手边有可立即操作的断电开关。

### 4.2 软件侧的固有安全动作

`MotorApp_ForcePowerStageSafe()` 在 **HAL 初始化之前**就把六路 PWM 引脚（PA8/9/10、PB13/14/15）置为推挽输出低电平，防止复位后引脚浮空被噪声耦合误导通 MOSFET。这一步**无条件执行、不做错误检查**。

上电后的正常时序是：功率桥保持关闭 → 前 1000 次 ADC 注入中断完成电流零偏校准 → 到达有效 `run` 请求才开 PWM。

> 也就是说：**上电后电机不会自己转**。必须显式发 `set run 1`。

## 5. 第一次上电

### 5.1 打开串口

~~~powershell
python -m serial.tools.miniterm COM27 2000000 --eol LF
~~~

把 `COM27` 换成实际端口。终端参数：**2,000,000 baud**，行结束符用 `LF`（控制台也接受 CR 与 CRLF）。

### 5.2 期望看到什么

上电完成零偏校准后，应看到类似：

~~~text
READY: set run 1 / set run 0 / status
~~~

**没有看到任何输出**时按顺序查：

1. 波特率是不是 2000000；
2. 串口是不是 USART1（PB6/PB7）；如果烧的是 HSE24 分支，那是 USART2（PB3/PB4）；
3. 晶振配置与板子是否一致；
4. 烧录地址与镜像布局是否匹配。

详细排查见[故障排查手册 §2.1](11-故障排查手册.md#21-串口完全没有输出)。

### 5.3 必看的三条自检

~~~text
status
~~~

在 `STATUS` 行确认：

| 字段 | 期望 | 不对时说明 |
|---|---|---|
| `cal=` | `1` | 零偏校准未完成，不允许启动 |
| `adc_irq=` | 持续增长 | 不涨 = 控制中断没跑，先别继续 |
| `adc_cfg=` | `1` | `0` = 注入序列与代码期望不符，**启动会被拒绝** |

`adc_cfg=0` 时 `STATUS` 附近还会多打印一行：

~~~text
ADC INJ MISMATCH expect ADC1 JL=3 JSQ=3,12,11,14 ; ADC2 JL=1 JSQ=3,17 ; adc_chk=…
~~~

现场临时绕过是 `set adc_chk 0`，但**采样通道是否可信需要自己判断**。

### 5.4 确认功率桥是关的

同一个 `STATUS` 行里看 `MOE=`，未启动时应该是 `0`。

## 6. 第一次闭环

### 6.1 最简命令序列

~~~text
set speed 1500
set run 1
status
set run 0
~~~

含义：

| 命令 | 作用 |
|---|---|
| `set speed 1500` | 设定目标转速 1500 rpm（只写目标，不启动） |
| `set run 1` | 提交运行请求；真正的启动在后续控制节拍里完成 |
| `status` | 看状态推进 |
| `set run 0` | 请求停机（由下一次 ADC 控制中断执行安全关断） |

> `set run 1` 只是"意图"。实际启动由 `MotorApp_Process` 与 ADC 控制节拍执行。

### 6.2 启动会依次经过四个阶段

| 阶段 | 控制角来源 | dq 参考 | 现场表现 |
|---|---|---|---|
| ALIGN | 固定电角度（0 rad = alpha 轴） | 只给 Id（1.0 A） | 转子被拉到已知位置，约 30 ms |
| OPEN_LOOP_IF | 虚拟电角度，按受限加速度爬升 | 只给 Iq（1.5 A） | 开环拖动，约 1.2 s 爬到验证转速 |
| OBSERVER_HANDOVER | 观测器角 + 渐消偏置 | 电流参考按坐标旋转搬运 | 控制角平滑交给观测器 |
| CLOSED_LOOP | 观测器磁链角 | 速度环输出 Iq | 双闭环运行 |

启动期间还有一组可信性判据在后台持续评估观测器是否可用，**只有判据持续成立才允许接管**。

### 6.3 怎么知道启动走到哪一步

~~~text
status
~~~

看 `START` 行的 `phase=`：

| phase | 含义 |
|---|---|
| `30` | 高速 I/F 加速段 |
| `31` | 高速 I/F 验证段 |
| `32` | 低速强制 I/F |
| `33` | 换向制动 |
| `10` | 闭环接管保持 |
| `12` | 高速闭环制动 |
| 其它 | 直接用状态机原始编号 |

### 6.4 建议同时开波形

~~~text
set wave_mode 1
set just_float 1
~~~

四种波形模式：

| `wave_mode` | 内容 |
|---|---|
| 0 | 三相电流 / 滤波转速 / 电角度 / 母线 / 原始转速（默认） |
| 1 | 启动时序 7 通道 |
| 2 | 电流跟踪 7 通道 |
| 3 | 控制速度 / 速度参考 / Iq_ref / Iq / Ud / Uq / Ulim |

帧格式：**7 个小端 float + 帧尾 `0x7F800000`（+Inf 位模式）= 32 字节**，1 kHz 抽样，忙则丢弃。

> 波形与文本诊断互斥：看文本诊断前先 `set just_float 0`。

### 6.5 通过判据

| 检查 | 期望 |
|---|---|
| `DRIVE rpm_f=` | 稳定在 1500 附近 |
| `CURRENT Id` | 接近 0 |
| `CURRENT sat_q` | 多数时间为 0 |
| `CURRENT Ulim` | ≈ `Vbus/√3` |
| `OBSERVER dtheta` | 稳定在负载角附近，不持续增长 |
| 相电流 | 三相幅值接近、无明显单相偏大 |

### 6.6 停机

~~~text
set speed 0
~~~

或

~~~text
set run 0
~~~

两者都表示停机。确认 `STATUS` 里回到 `state=IDLE`、`MOE=0`。

## 7. 常用命令与变量速查

| 命令 | 作用 |
|---|---|
| `help` 或 `?` | 命令帮助 |
| `list` | 列出变量与命令 |
| `get <名>` | 读一个变量 |
| `set <名> <值>` | 写一个变量 |
| `status` | 整组运行状态与诊断 |
| `startdiag` | 回放 接管 / 闭环 / 故障 三份锁存快照 |

四个最常用的可写量：

| 变量 | 典型用法 |
|---|---|
| `run` | `set run 0` / `set run 1`。故障闭锁后**必须先** `run 0` |
| `speed` | `set speed 1500`，范围 −15000 ~ 15000 rpm |
| `wave_mode` | `set wave_mode 0..3` |
| `just_float` | `set just_float 0/1` |

完整变量表（含范围与读写属性）见[参数与调参速查 §3](10-参数与调参速查.md#3-运行时可改串口-set--get-变量表)。

### 7.1 故障闭锁后的正确姿势

一旦故障锁存，串口会提示：

~~~text
FAULT latched: inspect startdiag; set run 0 before another start
~~~

正确顺序是：`startdiag` 取证据 → `set run 0` 解除闭锁 → 排除原因 → `set run 1`。

**直接再发 `set run 1` 会被忽略。**

## 8. 改配置的常见入口

| 想做什么 | 改哪里 | 注意 |
|---|---|---|
| 换电机 | `Core/Src/foc_math.c:74` 的 `Rs`/`Ls`/`flux_linkage`/`pole_pairs` | 六个量要一起改，观测器与电流标定都会受影响 |
| 调启动电流/加速度 | `Core/Src/motor_app.c:67`、`:74` | 空载先验证 |
| 调电流环/速度环增益 | `Core/Inc/controller.h` 的默认宏，或串口 `set speed_kp/speed_ki` | 改分频必须同步 `sample_time` |
| 调速度上限 | `Core/Inc/controller.h` 的 `FOC_SPEED_PI_OUTPUT_*` | 软件限幅 ≠ 硬件过流保护 |
| 改 PWM 频率 | TIM1 ARR + `foc.timer.pwm_arr` + `MOTOR_APP_CONTROL_HZ` | 三处必须同步 |
| 换串口 | `Core/Src/usart.c` + `motor_app.c` 的发送路径 | 24 MHz 分支用的就是另一组串口 |

改任何东西之前，先看[参数与调参速查 §5 调参前的固定检查](10-参数与调参速查.md#5-调参前的固定检查)与[§6 危险参数清单](10-参数与调参速查.md#6-危险参数清单)。

## 10. 环境里的已知坑

1. `.vscode/launch.json` 里有一个 `build/Boot-Debug/Observer.elf` 的 attach 配置，但 `CMakePresets.json` **没有** `Boot-Debug` 预设 —— 用之前需要自行配置对应目录。
2. `.vscode/tasks.json` 的烧录任务只覆盖 `Release`/`Debug` 两个 standalone 布局。
3. 工具链路径是绝对路径，换机器必改。
4. `COM27` 是硬编码端口号。
5. `build/` 被 `.gitignore` 排除，构建产物不入库。
6. `.clangd` 也被排除（`8f1dd80` 之后取消了跟踪），本地语言服务配置属于个人环境。
