# 故障排查手册（补充资料）

> 本文是**症状驱动的排查手册**：只回答"看到什么现象 → 采集什么证据 → 怎么下结论 → 怎么处理"。
> 控制原理见[控制层](02-控制层.md)，启动专题见[08 启动修正](08-双向静止启动与平滑接管修正.md)，验收步骤见[07 实施计划](07-完全实现实施计划.md)与[测试与验证指南](12-测试与验证指南.md)。
> 本文所有字段名、故障码与命令均取自当前源码；**改代码后本文可能陈旧，以源码为准。**

---

## 1. 排查前的固定动作

### 1.1 安全前置

1. **先断电再动线**：任何接线、探针、跳线改动都在母线上电之前完成。
2. **首次上电串限流**：用可调电源限流或串限流电阻，别直接接满功率电池。
3. **验证阶段空载**：无感启动的首次验证必须空载，并同时观察三相电流。
4. **手不离开断电开关**：出现异味、异响、电流失控时立即断电，不要靠软件停车。
5. **确认栅极安全**：`MotorApp_ForcePowerStageSafe()` 在 HAL 初始化前就把六路 PWM 引脚置低；若这一步被破坏（例如被人为提前跳过），上电瞬间就可能直通。

### 1.2 必须采集的最小数据集

一次失败的启动，**至少**要留下下面这些。少了任何一项，很多结论都无法下。

| 证据 | 获取方式 | 用途 |
|---|---|---|
| 完整启动日志 | 串口 `status`，以约 100 ms 间隔连续采 20 次以上 | 看趋势，不只看最后一帧 |
| 故障时刻锁存快照 | `startdiag`（打印 `HANDOVER` / `CLOSED` / `FAULT` 三段） | 看进入接管、进入闭环、跳故障三个时刻的状态 |
| 锁存的末拍失败位图 | `startdiag` 里的 `mask=0x…` | 判断失败瞬间是哪条判据不成立 |
| 实时失败位图与历史 | `status` 里的 `rdy_fail=` 与 `rdy_hist=` | 前者是当前拍，后者是**本次启动累计出现过**的失败位 |
| 判据连续计数 | `status` 里的 `rdy_count=` / `rdy_max=` / `span=` | 判断"从没通过"还是"通过后被清零" |
| 注入序列自检 | `status` 里的 `ADC … adc_cfg=` 行 | 排除采样通道根本没被转换 |
| 波形 | `set wave_mode` 选 1 / 2 / 3，配 `set just_float 1` | 看时序，不看单点数值 |

### 1.3 最小连通性检查

按顺序做完这三步，再谈别的问题：

~~~text
status
list
help
~~~

- `status` 有完整输出 → 串口输出链路、主循环、控制台解析都活着。
- `list` 能列出变量与命令 → 变量注册表建立成功（`MotorApp_Init()` 走到了注册那一步）。
- `help` 有输出 → 命令分发正常。

> 如果 `status` 里 `adc_irq=` 一直不增长，说明 **ADC 控制中断根本没跑**，此时所有控制类现象都不必分析，先解决中断与触发链路。

## 2. 症状 → 定位 → 处理

### 2.1 串口完全没有输出

| 项 | 内容 |
|---|---|
| 现象 | 上电后终端一个字符都没有 |
| 最可能原因（按可能性） | ① 波特率不对（应为 **2,000,000**）；② 接错串口（本板是 USART1 = PB6/PB7；原 `main` 的 CBU6 板是 USART2 = PB3/PB4）；③ 固件根本没跑起来（时钟/启动文件/Boot 布局）；④ TX DMA 或引脚被占用 |
| 需要采集的证据 | 示波器/逻辑分析仪看 PB6 是否有波形；若在跑 Boot 镜像，确认烧录地址是 `0x08005000`；确认使用的预设与实际板卡一致 |
| 判据 | 有波形但乱码 → 波特率或时钟树问题；无波形 → 固件未运行或引脚未复用 |
| 处理 | 核对 `CMakePresets.json` 里 HSE 与实际晶振；核对烧录地址与 `APP_FLASH_START`；用 SWD 挂调试器看是否卡在 `SystemClock_Config()` 或 `Error_Handler()` |
| 位置 | `Core/Src/main.c`、`Core/Inc/board_clock.h`、`Core/Inc/app_memory.h` |

> **跨板提醒**：24 MHz 的 `Boot-Release-HSE24` 预设串口是 USART2（PB3/PB4），此分支默认串口是 USART1（PB6/PB7）。在错误的串口口上不会看到 READY。

### 2.2 有输出但命令无响应 / 响应被截断

| 项 | 内容 |
|---|---|
| 现象 | 能收到 READY，但 `status` 无回复，或回复缺字 |
| 最可能原因 | ① 行结束符不被识别（本工程支持 CR、LF、CRLF）；② 一行超过 `DC_LINE_SIZE = 128` 字节 → `dc_line_overflow`，该行被丢弃；③ 环形队列溢出（`DC_RING_SIZE = 256`，高速灌数据会覆盖） |
| 证据 | `status` 后 `DebugConsole_GetOverflowCount()` 对应的溢出计数（若已通过诊断暴露）；缩短命令再试 |
| 判据 | 短命令能通、长命令不通 → 行缓冲上限；连续灌数据后丢失 → 环形队列溢出 |
| 处理 | 缩短命令、降低发送速率、确保每次以 CR 或 LF 结尾 |
| 位置 | `Core/Src/debug_console.c:21`（缓冲宏）、`:400`（行组装与溢出） |

### 2.3 CAN 没有心跳 / 收不到控制

| 项 | 内容 |
|---|---|
| 现象 | 上位机看不到周期反馈或心跳；发控制帧无效果 |
| 最可能原因 | ① 节点号不匹配（反馈/心跳 ID 是 `基址 + n`）；② 滤波器配置没放行该 ID；③ 波特率/采样点不匹配；④ 上位机把 FD 帧当经典帧发（控制帧是 24 字节 FD，旧版兼容帧才是 8 字节经典）；⑤ CRC8 不通过 |
| 证据 | 总线抓包看是否有任何帧；`HAL_FDCAN_RxFifo0Callback()` 是否在把帧搬进环形队列（RX FIFO0 中断）；主循环是否在消费队列 |
| 判据 | 总线上有帧但 MCU 无反应 → ID/滤波器/CRC；总线上一帧都没有 → MCU 未发送，看调度是否启动 |
| 处理 | 核对 `MOTOR_PROTOCOL_ID_*_BASE` 与节点号；确认上位机发的帧长与 DLC 一致；确认 BRS 关闭（仲裁段与数据段均 1 Mbit/s） |
| 位置 | `Core/Inc/motor_protocol.h:12`~`:38`、`Core/Src/motor_protocol.c`、`Core/Src/fdcan.c` |

> 控制帧 ID = `0x100`，周期反馈 = `0x200 + n`，心跳 = `0x280 + n`，调试反馈 = `0x300 + n`，HELLO = `0x380 + n`，Boot = `0x000`。逐字节布局见[通信与调试](04-通信与调试.md#can-协议-motor_protocolc)。

### 2.4 电机完全不动（PWM 无输出）

| 项 | 内容 |
|---|---|
| 现象 | 发 `set run 1` 后电机无任何反应 |
| 最可能原因 | ① ADC 注入配置自检不通过 → **启动被直接拒绝**；② 零偏校准未完成（`cal=0`）；③ 故障闭锁未解除（`latched=1`）；④ `MOE=0`，主输出未使能；⑤ 状态机停在 IDLE |
| 证据 | `status` 的 `STATUS` 行：`run=` `state=` `cal=` `idle_reset=` `adc_irq=` `MOE=` `latched=` `fail=`；`PWM` 行的 `CCER`/`CR1` |
| 判据 | `adc_cfg=0` → 采样自检拒绝（还会额外打印一行 `ADC INJ MISMATCH …`）；`cal=0` → 校准未完成；`latched=1` → 需先 `set run 0` 再 `set run 1` |
| 处理 | 见 §2.5 与 §4；`adc_cfg=0` 的临时绕过是 `set adc_chk 0`（**自行判断采样是否可信**） |
| 位置 | `Core/Src/motor_app.c:1374`（status ADC 行）、`:1378`（自检失败打印）、`:1694`（READY 提示）、`:1714`（run 被忽略） |

### 2.5 ADC 注入配置自检失败（起不来的最常见原因）

`status` 会打印：

~~~text
ADC JDR1=… JDR2=… JSQR=0x… adc_cfg=0
ADC INJ MISMATCH expect ADC1 JL=3 JSQ=3,12,11,14 ; ADC2 JL=1 JSQ=3,17 ; adc_chk=…
~~~

期望值（`Core/Src/motor_app.c:169`）：

| ADC | `JL` | Rank 1 | Rank 2 | Rank 3 | Rank 4 |
|---|---|---|---|---|---|
| ADC1 | 3 | 3（Ia, IN3） | 12（Ic, IN12） | 11（U 端, IN11） | 14（W 端, IN14） |
| ADC2 | 1 | 3（Ib, IN3） | 17（V 端, IN17） | — | — |

**历史事故**：`ScanConvMode = DISABLE` 时 HAL 会**静默截断**注入序列，V 相端电压曾因此从未被采样，`JDR2` 恒 0。所以 `JDR2=0` 有两种完全不同的解释：

- 序列被截断（V 相没被转换）→ 查 `JSQR` 与 `adc_cfg`；
- V 相实测确实是 0 V → 查接线与 OPAMP 配置。

`status` 的 `ADC` 行同时打印 `JSQR`，就是用来区分这两种情况的。

| 项 | 内容 |
|---|---|
| 处理 | 使 `adc.c` 的注入序列与上表一致；或在现场用 `set adc_chk 0` 临时绕过 |
| 位置 | `Core/Src/motor_app.c:169-176`、`Core/Src/adc.c`、`Core/Src/motor_app.c:1443`（`adc_chk` 注册） |

### 2.6 通电但不转 / 只抖动 / 堵转发热

| 项 | 内容 |
|---|---|
| 现象 | 有电流、有声音，转子只抖不连续旋转，或很快发烫 |
| 最可能原因 | ① 相序/接线与代码假设不符；② 定位电流不够或定位时间太短；③ I/F 拖动电流不足（重载失步）；④ I/F 加速度过大导致失步；⑤ 观测器参数（`Rs`/`Ls`/`flux_linkage`/`pole_pairs`）与电机不符 |
| 证据 | 波形模式 1（启动时序）；`status` 的 `OBSERVER` 行看 `flux=` 是否落在 `psi_min`~`psi_max`；`START` 行 `if_rpm=` 是否按预期爬升 |
| 判据 | `if_rpm` 爬升正常但 `flux` 长期越界 → 观测器/电机参数不匹配；`if_rpm` 爬不上去 → 拖动电流或加速度问题 |
| 处理 | 空载下先只验证 I/F 拖动（`set wave_mode 2`）；确认电机参数与 `foc_math.c:74` 的 R/L/磁链/极对数一致；确认三相接线与 `adc.c` 通道映射一致 |
| 位置 | `Core/Src/foc_math.c:73`（电机参数）、`Core/Src/motor_app.c:67`（ALIGN）、`:74`（I/F） |

### 2.7 启动卡在 I/f 验证超时（`fail=1`）

| 项 | 内容 |
|---|---|
| 现象 | 日志里 `fail=1`，或 `rdy_fail` 长期非 0，最终停机 |
| 含义 | `MOTOR_APP_FAIL_OBSERVER_NOT_READY`：**I/F 验证窗口内观测器始终不可信**（`Core/Src/motor_app.c:195`） |
| 最可能原因 | ① 观测器没锁到同一旋转磁场（转速不匹配）；② 磁链幅值越界；③ 单拍角/转速跳变超限；④ 窗口内没有累计覆盖整圈（`span` 不够）；⑤ 电流跟踪失败（Id 绝对值偏大或 Iq 偏差大） |
| 证据（**关键**） | `status`：`rdy_fail=`（当前拍）、`rdy_hist=`（本次启动累计出现过）、`rdy_count=`、`rdy_max=`、`span=`；`START` 行 `if_rpm=`、`dn=`（观测与虚拟转速差）、`hold=` |
| 判据 | `rdy_max` 很小且 `span` 接近 0 → 判据几乎没成立过，属于根本没同步；`rdy_max` 已接近 30 ms 对应拍数却被清零 → 某条判据周期性打断，查 `rdy_hist` 里哪位常驻 |
| 处理 | 按下表定位到具体位，见 §3.2 |
| 位置 | `Core/Src/motor_app.c:195`、`:207`（位定义）、`:91`~`:141`（判据参数） |

> **重要**：`rdy_hist` 是"本次启动累计出现过哪些失败位"，它比 `rdy_fail`（当拍）更能说明问题；而 `startdiag` 锁存的 `mask` 只代表**故障那一刻的当拍位图**。三者不要混用。

### 2.8 启动失败于接管/闭环健康检查（`fail=2`）

| 项 | 内容 |
|---|---|
| 含义 | `MOTOR_APP_FAIL_LOST_SYNC`：接管/闭环跟踪/磁链/掉速连续异常 |
| 注意 | `MOTOR_APP_CLOSED_LOOP_HEALTH_ENABLE = 0`，**当前台架策略已关闭高速电流误差自动停机**。因此若仍出现 `fail=2`，更可能来自接管阶段的检查，而不是闭环健康门限 |
| 证据 | `startdiag` 的 `HANDOVER` 段（是否走到接管）、`CLOSED` 段（是否进入闭环）；`status` 的 `OBSERVER` 行 `dtheta=` |
| 判据 | `HANDOVER: no snapshot` → 从未进入接管；`CLOSED: no snapshot` → 从未进入闭环 |
| 处理 | 先当作 `fail=1` 的延续处理；确认接管偏置渐变参数与 `delta` 趋势 |
| 位置 | `Core/Src/motor_app.c:196`、`:152`（健康开关） |

### 2.15 电流采样零偏异常 / 相电流明显不平衡

| 项 | 内容 |
|---|---|
| 现象 | 静止时 `Id`/`Iq` 不为 0 且随温度漂移；三相电流幅值差异大 |
| 最可能原因 | ① 零偏校准期间有电流（应在关桥状态完成）；② 增益 `gain_a/b/c` 与硬件不符；③ 某相通道映射错；④ 高占空比时未走重构 |
| 证据 | `status` 的 `cal=` 与 `CURRENT` 行；`ADC JDR1/JDR2` |
| 判据 | 关桥静止时 `Id`/`Iq` 不在 0 附近 → 零偏问题 |
| 处理 | 确认上电时功率桥确实关闭（`MOE=0`）；核对 5 mΩ / 24 倍增益 / 1.65 V 中点假设 |
| 位置 | `Core/Src/foc_math.c:50`（校准状态）、`:60`（增益）、`:47`（95% 重构阈值） |

### 2.17 观测器角度不收敛、转速乱跳

| 项 | 内容 |
|---|---|
| 最可能原因 | ① 电机参数不匹配（尤其 `Rs`/`flux_linkage`）；② 观测器增益 `gain` 不合适；③ PLL 参数不合适；④ 端电压来源/权重不对（低速应偏实测，高速应偏重构）；⑤ 磁链幅值越界 |
| 证据 | `status` 的 `OBSERVER` 行：`phase=`、`flux=`、`weight=`、`U/V/W=`、`ctrl=`、`dtheta=` |
| 判据 | `flux` 长期在 `psi_min`/`psi_max` 之外 → 磁链估计失效；`weight` 与转速关系反常 → 电压融合逻辑不对 |
| 处理 | 核对 `Core/Src/foc_math.c:81` 的观测器配置；核对 `MOTOR_APP_*_VOLTAGE_*_RPM` 迟滞；注意端电压 RC（100k/5.1k/68nF，`fc ≈ 482 Hz`）带来的相位滞后 |
| 位置 | `Core/Src/foc_math.c:81`、`Core/Src/motor_app.c:56` |

### 2.18 高速换向时出现振动或过流

| 项 | 内容 |
|---|---|
| 背景 | 2026-10-03 的运行修正针对高速闭环制动、±800 rpm 强制角穿零、有限接管保持窗口和电压饱和抗积分，见 [08](08-双向静止启动与平滑接管修正.md)。**该次未烧录，振动是否消除待实机波形验证** |
| 证据 | `set wave_mode 3` 的七通道（控制速度 / 速度参考 / Iq_ref / Iq / Ud / Uq / Ulim）；`status` 的 `CONTROL` 行 `sat_d`/`sat_q`/`speed_aw`/`brake` |
| 判据 | `sat_q` 长期非 0 且 `speed_aw=1` → 电压饱和与速度积分耦合，是低频摆动的候选原因；`brake=1` 表示当前处于高速闭环制动 |
| 处理 | 先确认是"电压饱和型"还是"滤波/延迟型"；`speed_slew` 可用来限制参考变化率（注意 `0` 是冻结参考） |
| 位置 | `Core/Src/motor_app.c:157`（保持窗口）、`:161`（运行 Iq 限速）、`:163`（速度控制滤波） |

> 速度 PI 使用 **100 Hz 单极点**滤波，而 30 Hz 双极点仍供显示与 Ready。两者不是同一个量，看波形时不要混。

### 2.19 停不下来 / 停车后仍有输出

| 项 | 内容 |
|---|---|
| 最可能原因 | ① 停止请求由**下一次 ADC 控制中断**执行，若中断已停则不会执行；② `MOE` 仍为 1；③ 状态机被冻结 |
| 证据 | `status` 的 `MOE=`、`PWM CCR=`；`state=` 是否回到 IDLE；`adc_irq=` 是否还在增长 |
| 判据 | `adc_irq` 停止增长但 `MOE=1` → 中断已停，停止动作不会执行，需要硬件断电 |
| 处理 | 确认 `FOC_PWM_Stop()` 被调用；确认 TIM1 仍在产生中断 |
| 位置 | `Core/Src/foc_math.c:138`（`FOC_PWM_Stop`）、`Core/Src/motor_app.c` 中断入口 |

### 2.20 接管后 `dtheta` 持续增长

| 项 | 内容 |
|---|---|
| 含义 | `dtheta` = 控制角 − 观测角（`status` 的 `OBSERVER` 行）。接管后应稳定在负载角附近 |
| 判据 | 持续增长 → 两个坐标系没有对齐（不是"负载角变大"那么简单） |
| 注意 | 停车后会混用保持控制角与复位后的观测角，**`dtheta` 在停机状态下没有故障前意义** |
| 处理 | 检查接管偏置渐变与坐标搬运路径 |
| 位置 | `Core/Src/motor_app.c:1365`（打印处）、`Core/Inc/controller.h:535`（搬运函数） |

## 3. 对照卡

### 3.1 启动失败码（`fail`）

来源：`Core/Src/motor_app.c:193`。

| 码 | 枚举 | 含义 | 下一步 |
|---|---|---|---|
| 0 | `NONE` | 无故障（兼作"新启动清零"） | — |
| 1 | `OBSERVER_NOT_READY` | I/F 验证窗口内观测器始终不可信 | 查 `rdy_hist`，见 §3.2 |
| 2 | `LOST_SYNC` | 接管/闭环跟踪/磁链/掉速连续异常 | 看 `startdiag` 的 `HANDOVER`/`CLOSED` 段 |
| 3 | `START_COMMAND` | 目标转速或启动参数非法 | 给非零、有限的目标转速 |
| 4 | `DIRECTION_CHANGE` | **保留码**，当前换向走 I/F 过零不再触发 | 若出现说明与设计不符，需人工核对 |
| 5 | `START_TIMEOUT` | 未进闭环总超时（4000 ms） | 先查为何没进接管 |
| 6 | `NONFINITE` | 关键浮点量 NaN/Inf | 查除零、`sqrt` 负数、被 `set` 写入的非法值 |
| 7 | `HANDOVER_CURRENT` | 接管电流异常 / 转矩反向 | 查 `Iq_ref` 与 `Iq` 的符号一致性 |
| 8 | `BUS_INVALID` | 母线电压非法 | 查母线采样与真实供电 |

> 编号可扩展，但**不要复用已用编号**。闭锁后必须先 `set run 0`，再 `set run 1` 才能重启。

### 3.2 ObserverReady 失败位图（`rdy_fail` / `rdy_hist` / `mask`）

来源：`Core/Src/motor_app.c:207`。串口显示范围 `0~0xFFF`（12 位）。

| 位 | 十六进制 | 枚举 | 含义 | 典型原因 | 下一步 |
|---|---|---|---|---|---|
| 0 | 0x001 | `PSI` | 磁链幅值越界（`psi_max<=0` 不查上限） | 电机参数不符 / 观测量发散 | 核对 `Rs`/`Ls`/`flux_linkage` 与 `psi_min`/`psi_max` |
| 1 | 0x002 | `INIT` | 观测器未初始化 | `Observer_Init()` 未执行或被复位 | 查初始化顺序（`FOC_Data_Init` → `MX_TIM1_Init` → `MotorApp_Init`） |
| 2 | 0x004 | `SPEED` | 转速低于下限（800 rpm） | 反电势不足 / 拖动没起来 | 看 `if_rpm` 是否爬升 |
| 3 | 0x008 | `DIR` | 转向与拖动方向不符 | 相序反、方向符号约定错 | 核对接线与 `if_direction` |
| 4 | 0x010 | `ANGLE_STEP` | 单拍观测角跳变超限（>0.35 rad） | atan2 跨 ±π、PLL 被扰动带飞 | 看波形模式 2 |
| 5 | 0x020 | `SPEED_STEP` | 单拍观测转速跳变超限（>100 rpm） | PLL 尖峰、观测噪声 | 查 PLL 参数与磁链质量 |
| 6 | 0x040 | `SYNC` | 绝对负载角超限（**当前检查关闭**） | — | 需要时把 `MOTOR_APP_OBSERVER_READY_ANGLE_CHECK_ENABLE` 置 1 |
| 7 | 0x080 | `TRACK` | 电流持续跟踪失败（2 ms 去抖） | Id 绝对值偏大或 Iq 偏差大、PI 饱和 | 查 `CURRENT` 行的 `Id`/`Iq`/`sat_d`/`sat_q` |
| 8 | 0x100 | `SPEED_MATCH` | 观测/虚拟转速偏差超限（40 rpm） | 观测器没锁在同一旋转磁场 | 看 `START dn=` |
| 9 | 0x200 | `DRIFT` | 窗口内相对锚点漂移超限（1.0 rad） | 慢漂、未真正同步 | 对比 `span` 与 `rdy_max` |
| 10 | 0x400 | `RAMP` | 尚未进入验证窗口（I/F 仍在加速） | 正常现象，早期必然置位 | 若长期只有该位 → 加速度/目标有问题 |
| 11 | 0x800 | `NONFINITE` | 判据输入出现 NaN/Inf | 同 `fail=6` | 查除零与非法写入 |

> `rdy_fail` 是**当前拍**的位图（遇 0 则整体清零）；`rdy_hist` 是**本次启动累计出现过**的位；`startdiag` 的 `mask` 是**故障锁存那一刻的当拍**位图。判读时要明确用的是哪一个。

## 4. 关键判据速查

| 观察项 | 正常表现 | 异常含义 |
|---|---|---|
| `STATUS adc_irq=` | 持续增长 | 不涨 → 控制中断未运行，先解决触发 |
| `STATUS cal=` | 上电后为 1 | 0 → 零偏校准未完成 |
| `STATUS MOE=` | 运行时 1，停机后 0 | 停机后仍为 1 → 允许再查 |
| `STATUS rdy=` | 进入接管后 1 | 长期 0 → 见 §3.2 |
| `STATUS rdy_max=` | 接近 30 ms 对应拍数 | 很小 → 从未真正通过判据 |
| `STATUS span=` | 增长到 ≥ 2π | 接近 0 → 没有净角度覆盖 |
| `DRIVE Vbus=` | 与万用表一致 | 偏差大 → 采样链路或通道顺序 |
| `CURRENT Ulim=` | ≈ `Vbus/√3` | 0 → 母线非法，电流环失去输出 |
| `OBSERVER flux=` | 落在 `psi_min~psi_max` | 越界 → 观测器失效 |
| `OBSERVER weight=` | 低速偏 1，高速偏 0 | 与转速无关 → 融合逻辑异常 |
| `CONTROL sat_q` | 稳态多为 0 | 长期非 0 且 `speed_aw=1` → 电压饱和耦合 |
| `TIMING max=` | 明显小于 6800 周期（40 µs） | 接近或超过 → 回调超预算，实时性受损 |
| `START phase=` | 按启动顺序推进 | 卡住不动 → 定位在对应阶段 |

## 5. 诊断盲区（单次快照得不出的结论）

下面这些**当前无法从一次 `startdiag` 快照得出**，必须靠连续 `status` 采样或波形：

1. **历史清零原因**：`rdy_count` 被清零是因为哪一位、在哪一拍，快照里没有记录时长。
2. **失败发生次数**：只有"最后锁存的那一次"，没有累计计数。
3. **Ready 通过的时长分布**：`startdiag` 快照不含 `ready_count`/`ready_max_count`。
   > 注意区分：**实时 `status` 行是有 `rdy_count`/`rdy_max`/`span`/`rdy_hist` 的**，缺的是**锁存快照**里的这几项。也就是说"实时能看到、事后看不到"。
4. **`HANDOVER: no snapshot` 的含义**：只说明没走到接管，不能说明为什么没走到。
5. **`CLOSED: no snapshot`**：不能把后续速度 PI 或接管补偿直接判为本次故障原因。
6. **`dtheta` 在停机后的意义**：会混用保持控制角与复位后的观测角，不能当作故障前的有效角差。
7. **重复读取同一快照不会恢复历史**：快照是覆盖式锁存，读多少次都是同一份。

因此排查时**优先用连续 `status` 采样**（记录时间戳），把快照当"定点证据"而不是唯一证据。

## 6. 硬件与接线类问题：用可观测的量反证

代码配置**不能替代外部硬件核对**。但可以用下面这些量做反证：

| 怀疑 | 怎么用软件反证 | 注意 |
|---|---|---|
| 某相电流没进来 | `ADC JDR1/JDR2` 与 `JSQR` 是否与期望一致 | `JDR2=0` 可能是"没被转换"也可能是"真的是 0 V" |
| 端电压通道接反 | `status` 的 `OBSERVER U/V/W` 三个值是否随转子位置合理变化 | 三个 OPAMP 是独立的，配置错误不会报错 |
| 母线电压读数错 | 与万用表对比 `DRIVE Vbus=` | 规则组 R1 才是母线，R2 是内部温度 |
| 栅极驱动没使能 | `STATUS MOE=` 与 `PWM CCER=` | `MOE=0` 时软件看起来"在跑"但桥臂不输出 |
| 相序反了 | `rdy_fail` 的 `DIR` 位（0x008） | 也可能是方向符号约定问题，不一定是接线 |
| 功率级发热异常 | `TIMING` 行、电流幅值、`if_iq` | 发热可能来自 I/F 电流偏大或长时间开环 |

> 三个独立 OPAMP 的引脚与 GPIO 模式由 `opamp.c`/`gpio.c` 配置，但**代码配置不能代替外部硬件电路核对**。
