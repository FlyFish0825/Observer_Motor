# 采样与板级：从电气量到控制拍

> 读图顺序：引脚 → ADC Rank → 原始码 → 物理量 → 算法输入 → PWM。下面的寄存器配置可由源码确认；外部电阻、RC、驱动极性和安全量程必须以原理图与实测核对。

## 1. 两类采样不要混在一起

| 采样组 | 量 | 触发/完成 | 软件读者 |
|---|---|---|---|
| ADC1/2 注入组 | 三相电流与三相端电压 | TIM1 CH4/TRGO 的下降沿；ADC1 JEOS | 25 kHz 中断入口 |
| ADC1 规则组 | 母线电压、MCU内部温度 | 主循环逐Rank软件触发、轮询完成 | BoardAdc_Update 后复制到 foc.state |

当前规则组不是固定1 kHz的硬实时任务；调用间隔取决于主循环、命令和打印耗时。注入组则以PWM触发为基准。用规则组有限的Vbus值给PWM定标，不代表已经实现快速母线过压保护。

来源：[`MX_ADC1_Init()`](../Core/Src/adc.c#L65)、[`MX_ADC2_Init()`](../Core/Src/adc.c#L186)、[`BoardAdc_Update()`](../Core/Src/board_adc.c#L21)、[`MotorApp_Process()`](../Core/Src/motor_app.c#L1826)。

## 2. 三相映射：哪只寄存器是哪一相

| 物理信号 | ADC输入引脚 | ADC通道 | 注入Rank | 中断读取 |
|---|---|---|---:|---|
| Ia / U电流 | PA2，OPAMP1输出 | ADC1 IN3 | 1 | ADC1 JDR1 |
| Ib / V电流 | PA6，OPAMP2输出 | ADC2 IN3 | 1 | ADC2 JDR1 |
| Ic / W电流 | PB1，OPAMP3输出 | ADC1 IN12 | 2 | ADC1 JDR2 |
| U相端电压 | PB12 | ADC1 IN11 | 3 | ADC1 JDR3 |
| V相端电压 | PA4 | ADC2 IN17 | 2 | ADC2 JDR2 |
| W相端电压 | PB11 | ADC1 IN14 | 4 | ADC1 JDR4 |
| 母线电压 | PA0 | ADC1 IN1 | 规则1 | HAL_ADC_GetValue |
| MCU温度 | 内部通道 | TEMPSENSOR_ADC1 | 规则2 | HAL_ADC_GetValue |

PA1/PA3是OPAMP1的输入脚，不是当前Ia的ADC结果脚。`FOC_Get_Iabc()` 的三个入参按 **Ia、Ib、Ic** 传入，不按ADC1所有寄存器排完再ADC2排序。

来源：[`Core/Src/adc.c`](../Core/Src/adc.c#L1)、[`Core/Src/opamp.c`](../Core/Src/opamp.c#L1)、[`MotorApp_OnInjectedConversion()`](../Core/Src/motor_app.c#L1877)。

## 3. 触发时序：同一次触发，不等于同时采完

```text
TIM1计数到CH4比较点，OC4REF产生配置的下降沿
  ├─ ADC1：Ia → Ic → U端电压 → W端电压 → JEOS
  └─ ADC2：Ib → V端电压
                               ↓
                 ADC1_2_IRQHandler → HAL → 应用回调
```

每个Rank经历采样/保持和转换，四个Rank有顺序延迟。ADC1完整序列完成时ADC2较短序列预期已完成，但软件自检并不验证每次触发的模拟建立时间；精确时间关系应结合ADC时钟、采样长度和真实触发测量。

当前公共ADC时钟配置为同步PCLK/4，12位；注入采样长度6.5周期，内部温度规则通道使用247.5周期。不能只用6.5除时钟估计整个转换序列，还要计入转换与触发等开销。

**源码触发沿是下降沿**，不是部分旧文档写的上升沿。中心对齐采样的意图是把低侧采样放在可测量窗口内，但“在峰值附近”本身不能证明运放已经稳定或每相下管都有效导通。

## 4. TIM1 与驱动引脚

| 资源 | 当前配置 | 说明 |
|---|---|---|
| 系统/TIM名义时钟 | 170 MHz | 正式16 MHz HSE经PLL；另有24 MHz测试变体 |
| TIM1 | 中心对齐，ARR=3399 | 工程名义25 kHz，Ts=40 μs |
| CH1/CH1N | PA8/PB13 | U相上/下桥控制 |
| CH2/CH2N | PA9/PB14 | V相上/下桥控制 |
| CH3/CH3N | PA10/PB15 | W相上/下桥控制；PB15复用AF4 |
| CH4 | CCR4=3398 | 只作ADC触发，不用作第四相 |
| DeadTime | DTG=90 | 当前时钟与编码下约0.529 μs，不是90 μs |
| Break / Break2 | 配置为禁用 | 不应在文档中画成已启用的硬件过流保护 |
| TIM6 | PSC169、ARR999 | 名义1ms，仅通信调度 |

ARR到周期的精确换算还受计数模式和更新事件定义影响，本手册采用工程配置的25kHz节拍；要验收完整时序应测PWM频率与ADC回调间隔，而不是只凭注释中的算式。来源：[`MX_TIM1_Init()`](../Core/Src/tim.c#L52)、[`MX_TIM6_Init()`](../Core/Src/tim.c#L161)、[`FOC_Data_Init()`](../Core/Src/foc_math.c#L33)。

## 5. 运放、零点和电流增益

三个OPAMP均是`OPAMP_STANDALONE_MODE`且`InternalOutput=DISABLE`。当前源码没有把内部PGA设置成24倍。电流换算采用5mΩ、24倍、3.3V参考的等效系数，这些外部电路假设需要与板级实物一致。

```text
gain = 3.3 / 4096 / (0.005 × 24)
     = 0.0067138671875 A/count
Iphase = (offset_phase − raw_phase) × gain_phase
```

注意减法方向。假设某相offset=2048，raw=1899，则计算电流约+1.0004A；raw=2197对应约−1.0004A。这个例子只是检验软件符号，不是当前实测零点。

三个通道的gain当前相同，但允许存在不同实际误差；每相有自己的校准均值。理想ADC满量程换算范围不是运放线性范围、MOSFET允许电流或电机热额定值。来源：[`FOC_Data_Init()`](../Core/Src/foc_math.c#L33)、[`FOC_Get_Iabc()`](../Core/Src/foc_math.c#L191)。

## 6. 零偏校准的条件和生命周期

上电前1000次注入回调分别累加 Ia、Ib、Ic原始码，再求平均。名义耗时1000×40μs=40ms。该阶段不跑观测器，不跑正常电流PI。必须保证桥未驱动且没有不应被算进零点的真实电流。

| 现象 | 应先看 | 不能直接下的结论 |
|---|---|---|
| cal一直为0 | adc_irq是否增加、CH4/触发是否启动 | “电机参数错误” |
| cal=1但零电流很大 | offset、原始码、通道/符号、外部偏置 | “把Iq增益调小即可” |
| 某相始终接近满量程 | 接线、运放饱和、供电参考 | “校准次数不够” |
| 停止再run零点未重算 | 当前实现保留校准结果 | “每次run都重新自校准” |

进入IDLE的控制器/观测器复位与上电零偏校准不是同一件事。来源：[`MotorApp_OnInjectedConversion()`](../Core/Src/motor_app.c#L1877)。

## 7. 高占空比电流重构：补救范围有限

`FOC_Get_Iabc()` 读三相CCR，选择最大者；当最大CCR严格超过配置的约95%阈值时，以另外两相和KCL重构该相：Ia=−Ib−Ic等。当前阈值整数约3229，**比较是大于，不是大于等于**。

这只解决“一个候选相的有效采样窗口不足”的情况。若两相同时不可测、另两相也被振铃污染，KCL并不能创造出真实反馈。应同时看CCR、原始码、驱动波形和重构相，而不能把重构后的三相和为零当成独立正确性证据——该等式本来就是算法强制的。

来源：[`FOC_Get_Iabc()`](../Core/Src/foc_math.c#L191)、[`FOC_Data_Init()`](../Core/Src/foc_math.c#L33)。

## 8. 端电压分压与RC：条件化计算，而非猜定板值

`BOARD_ADC_COUNT_TO_VOLTAGE` 使用：

```text
KV = 3.3/4096 × (100+5.1)/5.1 ≈ 0.016603 V/count
Uterminal = raw × KV
```

这是恢复输入侧电压的比例，ADC脚每计数仍约0.8057mV。三相端电压不是线电压；线电压Ua−Ub会消共模，Clarke也消理想共模。

若外部网络确为100k上臂、5.1k下臂，68nF从分压点到地，且信号源阻抗可忽略，则电容看到的戴维南电阻约为100k∥5.1k≈4.853kΩ：τ≈330μs，fc≈482Hz。仅取5.1k×68nF得到约347μs，是忽略上臂并联作用的近似；不是0.35μs。

```text
H(jω) = 1/(1+jωτ)
幅值 = 1/sqrt(1+(ωτ)²)
相位 = −atan(ωτ)
```

在1000机械rpm、7极对下电频率约116.7Hz，上述单极点模型相移约−13.6°。这只是特定拓扑的计算示例；电容位置、驱动源阻抗、额外抗混叠网络改变后，必须重新确定传递函数。不能无条件直接给观测角加固定13.6°。

## 9. 电压来源、母线年龄与发布方式

当前I/f按虚拟速度选择电压源，闭环按观测速度。>=1200选重构，<=900选实测，中间保持；权重线性过渡20ms。该迟滞不是电压测量有效性判断，没有独立“端电压快照超时”分支。

规则组先在局部`next`中组完母线和温度，全部成功才赋值给`board_adc_measurements`；出错只停止规则组并返回，旧值保留。共享结构只有四个字段，没有sequence、valid_age或seqlock。

主循环取到结果后分别写`foc.state.vbus`和温度；控制中断使用的是foc缓存而非直接调用规则组。因而若主循环长时间阻塞，有限的旧Vbus仍可能继续参与定标。诊断中记录采样更新时间/最坏间隔是后续可观测性改进项，本次文档没有实施它。

来源：[`BoardAdc_Update()`](../Core/Src/board_adc.c#L21)、[`BoardAdc_GetMeasurements()`](../Core/Src/board_adc.c#L58)、[`MotorApp_Process()`](../Core/Src/motor_app.c#L1826)。

## 10. ADC注入序列自检为什么必须保留

当前期望：ADC1 JL=3且JSQ=3,12,11,14；ADC2 JL=1且JSQ=3,17。JL存“转换数减一”。ADC2规则组只有一个通道，但注入组有两个Rank，所以扫描配置仍必须启用。

CubeMX重新生成时可能按规则组通道数恢复`ADC_SCAN_DISABLE`，使HAL组装注入序列走不同分支。结果可能不是报错，而是第二个Rank未被配置。软件会回读JSQR并拒绝不匹配的启动，不应为了让电机转而屏蔽这个证据。

检查顺序：**实际JSQR → 通道顺序 → JDR是否更新 → 引脚模拟量 → 换算与算法**。来源：[`MX_ADC2_Init()`](../Core/Src/adc.c#L186)、[`MotorApp_Init()`](../Core/Src/motor_app.c#L1694)。

## 11. IRQ优先级与DWT的使用边界

ADC与多个UART/DMA/CORDIC外设在配置中同为抢占优先级0，不能互相抢占。CAN为2，TIM6为3。更低优先级会让位，但已经运行的同级处理程序会造成等待；不能说“串口绝不会影响电流中断到达时间”。

当前`TIMING`按实际HCLK换算微秒并给占用率；新增wave_mode=4可输出耗时相关七通道。波形在本拍结束计时之前提交，因此时间通道反映最近已完成回调的统计，不是当前尚未计完的一拍。默认JustFloat仍关闭。

来源：[`Core/Src/dma.c`](../Core/Src/dma.c#L1)、[`Core/Src/usart.c`](../Core/Src/usart.c#L1)、[`Core/Src/adc.c`](../Core/Src/adc.c#L1)、[`MotorApp_DebugStatus()`](../Core/Src/motor_app.c#L1441)。

| 改动/症状 | 必须联动核对 | 证据 |
|---|---|---|
| 更换晶振 | BOARD_HSE_HZ、PLLM、串口/CAN/TIM | 时钟读回、通信位时序、PWM实测 |
| 改ARR/控制频率 | Ts、CONTROL_HZ、CH4点、所有计数阈值 | 回调间隔、限速每拍增量 |
| 调整规则组通道 | ScanConvMode、注入Rank、自检宏 | 两个JSQR与JDR |

## 源码走读与验证例题

### A. 一个计数误差在电流里有多大

当前1count约6.714mA。±1count的量化变化会进入Clarke和Park；若某相零点偏10count，约67mA的偏置不是“ADC分辨率噪声”，应先修零点。对gain的相对误差会按比例影响电流和转矩模型，零偏误差则在小电流时占比更大。

举例：2A电流、增益相对误差2%对应约40mA比例误差；10count零偏对应约67mA额外偏移。两个误差可能叠加，也可能偶然抵消，不能靠一个工况“看起来对了”校准全范围。

### B. 三路同步性与误差传播

Clarke中α=(2a−b−c)/3，所以a偏移ε会使α偏2ε/3；b偏移ε还会令β偏ε/√3。不同Rank的采样时刻差可近似转成Δi≈(di/dt)Δt，电流变化最快的PWM切换附近往往更敏感。

ADC转换设置正确只确认“读了指定通道”。要确认“读到可以代表本拍电流的量”，还需低侧窗口、运放恢复、采样电容建立和布线噪声证据。阈值重构仅在算法层补救一相，不会解决多相同时失效。

### C. 一次规则组失败如何处理

[`BoardAdc_Update()`](../Core/Src/board_adc.c#L21)

以下为当前实现的阅读摘录，移除注释与空行；省略外围内容时不改变原控制分支的含义。

```c
HAL_StatusTypeDef BoardAdc_Update(void) {
  BoardAdcMeasurements_t next = {0};
  uint16_t adc1_values[2];
  for (uint32_t rank = 0U; rank < 2U; rank++) {
    if (HAL_ADC_Start(&hadc1) != HAL_OK) {
      (void)HAL_ADCEx_RegularStop(&hadc1);
      return HAL_ERROR;
    }
    if (HAL_ADC_PollForConversion(&hadc1, 10U) != HAL_OK) {
      (void)HAL_ADCEx_RegularStop(&hadc1);
      return HAL_TIMEOUT;
    }
    adc1_values[rank] = (uint16_t)HAL_ADC_GetValue(&hadc1);
  }
  next.vbus_raw = adc1_values[0];
  next.temperature_raw = adc1_values[1];
  next.vbus_voltage = (float)next.vbus_raw * BOARD_ADC_COUNT_TO_VOLTAGE;
  next.temperature_c = (float)__HAL_ADC_CALC_TEMPERATURE(
      3300U, next.temperature_raw, ADC_RESOLUTION_12B);
  board_adc_measurements = next;
  return HAL_OK;
}
```


这里的失败返回不会主动改写旧Vbus为0，因此控制入口的“Vbus有限且>0.1”无法检测所有陈旧数据。主循环打印很慢时，需要单独观察采样年龄；不能因为轮询每Rank设置10ms超时就宣称总调度延迟只有10ms。

### D. 注入组启用后为何还要改JEOS

[`MotorApp_Init()`](../Core/Src/motor_app.c#L1694)

以下为当前实现的阅读摘录，移除注释与空行；省略外围内容时不改变原控制分支的含义。

```c
if (HAL_ADCEx_InjectedStart(&hadc2) != HAL_OK) return HAL_ERROR;
  if (HAL_ADCEx_InjectedStart_IT(&hadc1) != HAL_OK) return HAL_ERROR;
  jsqr1 = ADC1->JSQR;
  jsqr2 = ADC2->JSQR;
  jl1 = (jsqr1 & ADC_JSQR_JL) >> ADC_JSQR_JL_Pos;
  jl2 = (jsqr2 & ADC_JSQR_JL) >> ADC_JSQR_JL_Pos;
  adc_inj_ok = 1U;
  if ((jl1 != MOTOR_APP_ADC1_INJ_JL) ||
      (MOTOR_APP_JSQR_FIELD(jsqr1, JSQ1) != MOTOR_APP_ADC1_INJ_JSQ1) ||
      (MOTOR_APP_JSQR_FIELD(jsqr1, JSQ2) != MOTOR_APP_ADC1_INJ_JSQ2) ||
      (MOTOR_APP_JSQR_FIELD(jsqr1, JSQ3) != MOTOR_APP_ADC1_INJ_JSQ3) ||
      (MOTOR_APP_JSQR_FIELD(jsqr1, JSQ4) != MOTOR_APP_ADC1_INJ_JSQ4)) {
    adc_inj_ok = 0U;
  }
  if ((jl2 != MOTOR_APP_ADC2_INJ_JL) ||
      (MOTOR_APP_JSQR_FIELD(jsqr2, JSQ1) != MOTOR_APP_ADC2_INJ_JSQ1) ||
      (MOTOR_APP_JSQR_FIELD(jsqr2, JSQ2) != MOTOR_APP_ADC2_INJ_JSQ2)) {
    adc_inj_ok = 0U;
  }
  if (adc_inj_ok == 0U) {
    DebugConsole_Printf("ADC INJ FAIL ADC1 JSQR=0x%08lX JL=%lu ADC2 JSQR=0x%08lX JL=%lu\r\n",
        (unsigned long)jsqr1, (unsigned long)jl1,
        (unsigned long)jsqr2, (unsigned long)jl2);
    DebugConsole_Printf("ADC INJ expect ADC1 JL=3 JSQ=3,12,11,14 ; ADC2 JL=1 JSQ=3,17 ; run disabled\r\n");
  }
  motor_adc_cfg_ok = adc_inj_ok;
  __HAL_ADC_DISABLE_IT(&hadc1, ADC_IT_JEOC);
  __HAL_ADC_ENABLE_IT(&hadc1, ADC_IT_JEOS);
  TIM1->CCR4 = foc.timer.adc_trigger;
  if (HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_4) != HAL_OK) return HAL_ERROR;
  return HAL_OK;
}
```


函数名InjectedStart_IT不保证最终采用的是你希望的“整序列完成”事件；后续中断位选择和共享IRQ分发都必须一起读。若每个Rank触发一次控制，控制周期和各通道数据年龄都会错位。

### E. 六个边界测试的观测目标

| 条件 | 应记录 | 通过判据的口径 |
|---|---|---|
| 空载关桥 | 各相raw、offset、换算后电流 | 偏置/噪声范围已定义，不将真实电流混入校准 |
| 正负已知电流 | 原始码和仪表基准 | 方向、比例和相间偏差一致 |
| PWM接近95% | 三相CCR、raw、重构相 | 明确阈值前后的算法行为，验证另两相仍可测 |
| 控制台密集输出 | ADC回调间隔、DWT、母线更新 | 不仅平均占用满足，最坏延迟有余量 |
| 规则组超时 | 最新值与保留值、更新年龄 | 失败不破坏注入触发，陈旧值可被辨识 |
| 重新生成CubeMX | ADC2扫描、JSQR、TRGO沿、IRQ位 | 软件配置与文档基准逐项一致 |

这些是计划中的验收目标，不表示本轮已经向硬件施加相应条件。
