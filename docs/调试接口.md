# 调试接口使用说明

本文对应当前 `Observer_Motor` 工程代码，供后续开发者直接接入调试输出。**中断只提交数值，主循环格式化文本，DMA 后台发送；JustFloat 保持原始二进制帧，不经过文本格式化。** 本文的接口、缓冲区大小和行为均以当前实现为准，不代表规划中的功能。

## 1. 文件与硬件

| 位置 | 作用 |
|---|---|
| `App/Communication/debug_console.h` | 对外接口、日志类型、命令/变量注册 |
| `App/Communication/debug_console.c` | RX DMA/命令解析、通用数值队列、主循环格式化、`DebugConsole_Printf()` |
| `Core/Src/main.c` | `DebugConsole_Tx()` 文本入队、`DebugConsole_TxProcess()` TX DMA 调度、`JustFloat_Init()` 和 `Fast_Send_6Floats()` |
| `App/Calibration/motor_calibration.c` | Rs 辨识中断日志的实际调用示例 |
| `Core/Src/usart.c` | USART2 外设、收发 DMA 配置 |

当前 USART2 为 **2,000,000 baud、8N1、无硬件流控**；PB3=TX、PB4=RX，TX 使用 DMA1 Channel1，RX 使用 DMA1 Channel2。上位机应设置相同的波特率。不要把项目里的旧 115200 注释误认为当前配置。

## 2. 选择哪种接口

| 使用场景 | 调用接口 | 调用上下文 | 输出 |
|---|---|---|---|
| ADC、CAN、EXTI 等中断提交少量数值 | `DebugConsole_LogFromISR(...)` | 中断 | 只入数值队列；主循环稍后转成文本 |
| 主循环打印提示、结果、错误、命令回复 | `DebugConsole_Printf(...)` | 主循环 | 格式化文本入 TX 队列 |
| 正常 FOC 波形送 VOFA+ | `Fast_Send_6Floats(...)` | 当前在 ADC 控制回调中调用 | 原始 28 字节 JustFloat 二进制帧 |
| 仅判断数值日志队列是否清空 | `DebugConsole_LogPending()` | 主循环，或 JustFloat 的轻量让路判断 | `true`=尚有未格式化的数值日志 |

**禁止在高频中断中调用 `DebugConsole_Printf()`、标准 `printf()`、`vsnprintf()` 或任何等待串口的函数。** 在中断里只调用 `DebugConsole_LogFromISR()`；即使写入失败也不等待。

## 3. 当前完整数据流

### 文本/数值日志

```text
ADC/CAN/其他中断
    │ DebugConsole_LogFromISR(type, info, a, b, c)
    ▼
dc_log[32] 数值环形队列（中断写、主循环读）
    │ 主循环 DebugConsole_LogProcess()，每次最多取 4 条
    ▼
DebugConsole_Printf() → vsnprintf() 到 192 字节临时缓冲
    │ DebugConsole_Tx() 整条文本入队，不等待发送完成
    ▼
debug_tx_ring[4096] 文本 TX 环形缓冲区
    │ 主循环 DebugConsole_TxProcess() 调度
    ▼
USART2 TX DMA → 上位机文本窗口
```

- `dc_log[32]` 实际可排队 **31 条**（留一个空槽区分满/空）。每条记录包括 `type`、`info`、三个 `float`，记录由多个不同优先级中断写入，入队时使用极短临界区。
- 数值队列满时，`DebugConsole_LogFromISR()` 返回 `false`、增加丢弃计数，**不会等待**。主循环队列清空后会输出类似 `WARN: 3 debug logs dropped`。
- `DebugConsole_Printf()` 每次先格式化一条消息；超过 192 字节时当前实现会截断为最多 **191 字节**。
- 文本 TX 缓冲区为 4096 字节，实际最多排队 4095 字节；空间不足时丢弃**整条新消息**，随后可输出 `WARN: USART2 TX queue overflow`。
- `DebugConsole_LogPending()==false` 仅表示**数值队列已被主循环取空**，不表示文本 TX 缓冲区和 UART 已全部发完。
- 当前 `DebugConsole_Tx()`、`DebugConsole_TxProcess()` 在 `main.c` 中为 `static`，其他模块不要绕过 `DebugConsole_Printf()` 直接操作 USART2 TX DMA。

### JustFloat（二进制独立路径）

```text
正常 FOC ADC 回调（仅在当前波形开关允许、TX 空闲时）
    │ Fast_Send_6Floats(f0, f1, f2, f3, f4, f5)
    ▼
tx_frame：6 × IEEE-754 float32 + uint32_t tail
    │ DMA CMAR → tx_frame；CNDTR → 28
    ▼
USART2 TX DMA → VOFA+ JustFloat 解析
```

JustFloat **不进入 `dc_log[]`、不调用 `DebugConsole_Printf()`、不转换成 ASCII**。文本/数值日志优先，已有的 28 字节 JustFloat 帧先发完；有待发送文本时暂不启动新波形帧，待文本队列清空且串口发完后恢复。USART2 是同一条物理字节流：**文本和二进制帧会在不同时间段交替出现**，所以需要纯净 VOFA 波形时应暂时关闭 JustFloat 以外的文本日志；调试纯文本时先关 JustFloat。

## 4. 通用中断数值接口

头文件：

```c
#include "debug_console.h"

bool DebugConsole_LogFromISR(uint8_t type, uint16_t info,
                             float a, float b, float c);
```

参数说明：

| 参数 | 含义 |
|---|---|
| `type` | 记录类型（`DebugLogType_t`），决定主循环输出格式 |
| `info` | 16 位整数标签，例如通道号、序号或模块自定义编号 |
| `a, b, c` | 最多三个 `float` 数值；没用的传 `0.0f` |
| 返回值 | `true` = 已成功入队；`false` = 队列满，当前记录未入队 |

当前已实现的类型：

| 类型 | `info` 规则 | 主循环打印格式 |
|---|---|---|
| `DEBUG_LOG_VALUES`（0） | 调用者自定义编号 | `LOG <info>: <a> <b> <c>`，数值保留四位小数 |
| `DEBUG_LOG_RS_POINT`（1） | 高 8 位是相别 0=AB/1=BC/2=CA，低 8 位是点序号 | `AB 01: duty=... V=... I=...` |
| `DEBUG_LOG_RS_RESISTANCE`（2） | 相别 0/1/2 | `R_AB = ... ohm` 等 |

当前实现对非 Rs 类型统一按 `DEBUG_LOG_VALUES` 的格式输出。**自定义新类型如果需要特殊标签、单位或精度，要在 `debug_console.h` 增加枚举，并在 `DebugConsole_LogProcess()` 增加对应格式分支；不要在 ISR 里拼字符串。**

### 例程 A：ADC 中断记录三个量（最常用）

```c
#include "debug_console.h"

void My_AdcCallback(float speed_rpm, float iq, float vbus)
{
    /* 只提交数值，不格式化；通用输出的编号 10 由本模块定义。 */
    (void)DebugConsole_LogFromISR(DEBUG_LOG_VALUES, 10U,
                                  speed_rpm, iq, vbus);
}
```

对应文本：

```text
LOG 10: 1200.0000 1.2500 24.0000
```

不要在每个 25 kHz 中断周期都入队，否则会远超文本格式化和 UART 带宽。推荐在已有的周期计数/状态变化条件下低频记录：

```c
/* 示例：该回调确实以 25 kHz 调用时，每 250 次约输出一条（100 Hz）。 */
static uint16_t log_divider;
if (++log_divider >= 250U) {
    log_divider = 0U;
    (void)DebugConsole_LogFromISR(DEBUG_LOG_VALUES, 10U,
                                  speed_rpm, iq, vbus);
}
```

若应用关注不能丢的关键故障，不要把这个尽力而为的日志队列当作故障锁存或安全保护机制；先把故障记录在业务状态中，再异步打印。

### 例程 B：检查入队失败（可选）

```c
if (!DebugConsole_LogFromISR(DEBUG_LOG_VALUES, 20U,
                              current_a, current_b, current_c)) {
    /* 只设置业务统计/标志；不在中断中重试、等待或 printf。 */
}
```

系统本身已有总丢弃数统计和主循环告警；多数调试点只需将返回值显式转为 `(void)`。

### 例程 C：Rs 辨识当前真实用法

每档平均采样完成后，`motor_calibration.c` 写入：

```c
DebugConsole_LogFromISR(DEBUG_LOG_RS_POINT,
    (uint16_t)(((uint16_t)motor_cal.phase << 8) | motor_cal.point_count),
    p->duty, p->voltage, p->current);
```

单相拟合完成后，写入：

```c
DebugConsole_LogFromISR(DEBUG_LOG_RS_RESISTANCE,
                        (uint16_t)finished_phase,
                        line_r, 0.0f, 0.0f);
```

主循环先运行 `DebugConsole_LogProcess()`，再运行 `MotorCalibration_DebugProcess()`。后者等数值日志排空再打印最终 `R_A/R_B/R_C/R_S` 或错误。Rs 原有的 `point[]` 仍用于拟合，不是日志队列。

## 5. 主循环文本接口

```c
#include "debug_console.h"

/* 在主循环、命令处理函数等非高频中断上下文使用。 */
DebugConsole_Printf("observer: rpm=%.1f iq=%.3f A\r\n",
                    speed_rpm, iq);
DebugConsole_Printf("result: Rs=%.6f ohm\r\n", rs);
```

它在主循环调用 `vsnprintf()`，将一条文本放进 TX 环形缓冲区后返回；**不代表串口已发完**。请控制单条输出长度与调用频率。打印量持续高于 2 Mbaud 可承受的字节率时，队列会满并丢记录。

标准 C `printf()` **不是相同路径**：当前 `main.c` 的 `_write()` 仍调用阻塞式 `HAL_UART_Transmit()`，会绕开文本 TX 队列，也可能与 JustFloat 或 DMA 文本发送冲突。新模块应统一使用 `DebugConsole_Printf()`，不要直接操作 `huart2` 的 TX。

## 6. JustFloat 的原始格式及例程

当前 `main.c` 中的原始帧定义：

```c
typedef struct {
    float data[6];
    uint32_t tail;
} JustFloatFrame_t;

_Static_assert(sizeof(JustFloatFrame_t) == 28U,
               "VOFA JustFloat frame must be 28 bytes");
```

初始化时设置：

```c
tx_frame.tail = 0x7F800000UL;
```

每帧在 STM32G431 小端模式下的布局：

| 字节偏移 | 内容 |
|---:|---|
| 0～23 | 六个连续 IEEE-754 **float32**，按 `f0`～`f5` 排列 |
| 24～27 | `0x7F800000` 的小端字节序：`00 00 80 7F` |

因此帧长恒定 **28 字节**；末尾四字节是 VOFA+ JustFloat 识别帧边界的关键，**不能删、不能替换成换行符、不能做成十六进制文本**。不要通过 `DebugConsole_Printf("%f", ...)`、`sprintf()` 或 ASCII 通道发送 JustFloat。

当前正常 FOC 回调里的真实例程：

```c
Fast_Send_6Floats(
    foc.state.i_dq.d,
    foc.state.i_dq.q,
    foc.observer.state.speed_rpm,
    foc.observer.state.psi_mag,
    foc.observer.state.phase_raw * RAD_TO_DEG_F,
    foc.observer.state.pll_phase * RAD_TO_DEG_F);
```

对应通道顺序依次为 Id、Iq、转速 rpm、磁链幅值、原始相位角（°）、PLL 相位角（°）。外围代码先检查日志队列、TX 队列、USART TC 和 DMA 剩余计数，只在允许启动新帧时计算并调用。

接口 `Fast_Send_6Floats(f0, ... f5)` 返回 `0` 表示本帧已启动 DMA，返回 `-1` 表示关闭、已有发送占用或有文本待发；它**不排队等待**，忙时直接跳过该帧，以保持实时性。DMA 正在读取的 `tx_frame` 不得提前改写。

## 7. 初始化和任务调度（现有 main.c，勿重复添加）

```c
/* 外设初始化完成后，当前 main.c 已进行： */
JustFloat_Init();
if (DebugConsole_Init(&huart2, DebugConsole_Tx) != HAL_OK) {
    Error_Handler();
}

/* 已存在的主循环顺序： */
while (1) {
    ADC_Regular_Service(HAL_GetTick());
    MotorProtocol_Process();
    DebugConsole_Process();        /* RX 命令处理 */
    DebugConsole_LogProcess();     /* 中断数值 → 文本，至多 4 条 */
    MotorCalibration_DebugProcess(); /* Rs 最终汇总 */
    DebugConsole_TxProcess();      /* 文本 TX DMA 调度 */
    /* 原有其他任务 */
}
```

`DebugConsole_Tx()` / `DebugConsole_TxProcess()` 在 `main.c` 中是内部 `static` 实现；**后续模块只需包含 `debug_console.h` 并调用公开接口，不应复制初始化、主循环任务或底层 DMA 代码**。RX DMA 命令接收与 TX DMA 是两条独立方向，新增输出不需要修改 RX 接收回调。

## 8. 串口命令、JustFloat 开关及观察工具

串口接收命令在 `DebugConsole_Process()` 中解析，内置：`help`、`list`、`get <name>`、`set <name> <value>`。`main.c` 已注册 `just_float` 布尔变量，开机时 `JustFloat_Init()` 默认将其设为 1（启用）。

需要纯文本时，在支持收发的文本串口工具中发送：

```text
set just_float off
get just_float
```

需要恢复 VOFA+ 二进制波形时：

```text
set just_float on
```

布尔值也接受 `0/1/true/false`。例如 `set just_float 0` 与 `off` 等价。串口文本命令需发送完整的一行（换行结束）。

- **看纯文本日志**：先关闭 JustFloat，再用 2,000,000 baud、8N1 的文本串口工具查看。
- **看 VOFA+ 波形**：使用 VOFA+ 的 **JustFloat** 协议解析 6 路 float32、保留 4 字节帧尾；尽量避免同时输出文本，防止混合字节流影响连续解析。
- **不能只凭能看到一帧判断全部日志正常**：多条输出还需检查数值队列和 DMA 是否持续推进，以及是否报告队列溢出。
- `DebugConsole_GetOverflowCount()` 返回的是**RX 命令环形缓冲区的溢出计数**，不是 TX 队列或数值日志的丢弃计数。

## 9. 以后添加一个新的自定义文本格式

目前 `DEBUG_LOG_VALUES` 已满足通用的“编号 + 三个浮点数”，应优先直接用它。如果确实需要专用名称和单位：

1. 在 `debug_console.h` 的 `DebugLogType_t` 枚举末尾加一个类型，例如 `DEBUG_LOG_MOTOR_TEMP`。
2. 在 `debug_console.c` 的 `DebugConsole_LogProcess()` 内按类型分支，用 `DebugConsole_Printf()` 格式化；不要把格式化搬进中断。
3. 在目标模块的中断中调用 `DebugConsole_LogFromISR(DEBUG_LOG_MOTOR_TEMP, info, a, b, c)`。
4. 控制输出频率并验证队列满时不会影响 ADC、PWM 或故障保护。

**不要另建一套 UART TX DMA，不要把 JustFloat 二进制帧塞入数值日志/文本队列，不要为了打印改变电机采样与控制时序。**

## 10. 当前边界与验收

- 当前仅设计为**调试信息尽力而为**：日志队列、文本 TX 队列满时可能丢内容，不能代替完整数据记录或关键故障处理。
- 同一 USART2 的二进制和文本采用时间复用，不是两个可同时独立解析的物理串口。发送文本期间 JustFloat 不启动新帧，但不会将已发送的二进制内容撤回。
- 在目前的实现里，`Fast_Send_6Floats()` 使用原始 DMA 通道寄存器，`DebugConsole_TxProcess()` 共用这个 DMA；不要从新模块直接调用底层发送/改 DMA 状态。
- 编译成功不等于实机波形已验收。修改时至少检查：连续多条文本正常、AB/BC/CA 逐档及各相电阻顺序正确、JustFloat 帧长与尾码不变、DMA 文本结束后波形恢复、溢出时不中断控制环。
